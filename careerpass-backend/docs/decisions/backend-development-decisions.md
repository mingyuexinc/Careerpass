# 后端开发决策

> 文档性质：记录跨垂直切片（Vertical Slice）持续有效的长期开发原则和重要架构、工程决策。
>
> 不承担职责：不定义当前版本交付范围、具体业务字段、单个切片方案、任务清单或外部能力专项验证结果。

## 1. 决策范围

本文件只记录以下长期有效的决策：

- 后端如何与已存在的正式前端协作；
- 前后端如何通过应用程序接口契约（API Contract）协作；
- 后端如何按垂直切片（Vertical Slice）交付用户闭环；
- 后端分层、模块边界、数据访问和状态拥有者如何约束；
- 外部能力、智能体工作流（Agent Workflow）和异步能力如何按需启用；
- 代码、测试、真实前端接入和端到端验证（End-to-End，E2E）如何形成反馈闭环；
- 旧资产如何迁移，以及长期决策发生变化时如何回退。

当前版本范围、产品目标和延期能力由后端交付范围文档负责；具体业务规则、领域模型、数据库结构和切片规格由对应文档负责。

## 2. 前端优先的后端开发决策

正式前端存在时，后端以真实前端用户流程作为能力发现入口，但不把前端页面直接等同于后端必须实现的范围。后端仍以领域规则、资源归属、状态模型和安全边界裁决真实行为。

后端开发采用以下长期顺序：

```text
前端用户流程
  → 后端能力映射
  → 后端现状差距分析（Gap Analysis）
  → 应用程序接口契约（API Contract）定义与锁定
  → 不确定外部能力验证
  → 垂直切片（Vertical Slice）方案
  → 切片任务拆分
  → 后端实现
  → 单元、接口和集成测试
  → 真实前端接入
  → 端到端验证（End-to-End，E2E）
```

前端提供操作、页面状态和可观察结果；后端负责业务事实、状态迁移、权限校验和副作用控制。前端已有实现不能替代后端的范围裁决、契约锁定或测试证据。

## 3. 契约优先（Contract-First）决策

### 3.1 应用程序接口契约

前后端通过版本化应用程序接口契约（API Contract）协作。契约至少明确：

- 路径、方法、请求字段和响应字段；
- 统一响应结构 `{code, msg, data}`；
- 成功、处理中、空数据和失败行为；
- 认证、资源归属和敏感字段边界；
- 异步任务状态和查询语义；
- 生产者、消费者、状态拥有者和事务责任。

契约锁定后，后端实现和真实前端接入只能依赖锁定版本。字段、状态、触发语义或责任边界变化时，必须创建新版本，或让所有受影响参与方回退后重新锁定。

### 3.2 契约不是前端字段转录

前端字段只是契约输入，不能单独决定业务事实。遇到前端需要但后端不存在的字段时，必须先判断其范围、事实来源、状态影响、授权影响和是否应延期；不能为满足页面显示而直接新增领域字段或业务状态。

## 4. 垂直切片（Vertical Slice）决策

### 4.1 切片定义

垂直切片（Vertical Slice）是从真实前端操作开始，经过后端业务处理、数据持久化或任务执行，最终回到真实前端可观察结果的最小用户闭环。

切片不是单个页面、单个数据库表或单个技术组件。一个切片可以跨越控制器层（Controller）、服务层（Service）、仓储层（Repository）、数据模型、异步任务和外部适配器，但参与模块只能通过公开契约协作。

### 4.2 切片边界

每个切片开始前必须明确：

- 用户目标和前端触发场景；
- 本切片必须交付和明确不做的内容；
- 上游输入、下游结果和资源所有者；
- 已有能力及其证据；
- 应用程序接口契约（API Contract）、数据和状态变化；
- 外部能力、异步任务和副作用；
- 单元、接口、集成和端到端验收标准。

旧文档中已经出现的实体、字段或页面，不会自动进入当前切片。切片按用户闭环和依赖关系排序，不按代码目录或技术层横向铺开；前置切片只交付后续切片实际需要的最小公开能力。

## 5. 架构与工程边界决策

### 5.1 分层职责

- 控制器层（Controller）：负责协议解析、身份上下文和统一响应，不承载领域编排细节。
- 服务层（Service）：负责用例编排和业务规则调用，不直接编写 SQL 或访问对象关系映射会话。
- 仓储层（Repository）：负责数据访问、资源归属校验和持久化边界。
- 基础设施层（Infrastructure）：负责数据库、缓存、对象存储、消息队列和外部适配器，不拥有业务领域状态。
- 智能体工作流（Agent Workflow）：只能调用已注册且输入经过校验的工具，不得越过服务层和仓储层访问内部实现。

### 5.2 资源与状态边界

- 每个业务资源必须有唯一状态拥有者；其他模块只能通过版本化请求、结果或事件交接。
- 用户资源必须校验当前用户和资源归属，不能仅凭资源标识读取或修改。
- 状态变化必须通过合法迁移和既定业务用例完成，不能直接更新状态字段绕过领域规则。
- 模块之间不得反向依赖对方的服务实现、仓储实现、对象关系映射模型或内部任务生命周期。

### 5.3 不可降级的安全边界

无论当前版本规模大小，以下边界不能为了演示便利而省略：

- 密码、令牌、原始敏感资料、完整内部定位和模型原始响应不得进入日志、追踪或非必要响应；
- 大语言模型（LLM）输出必须经过结构化和业务规则校验后才能入库或驱动流程；
- 对外投递、真实消息发送和其他不可逆副作用必须有明确授权与审计记录；
- 工具输入必须校验，外部调用必须设置合理的超时、错误处理和适用的重试边界；
- 实际使用的异步任务必须可追踪、幂等并能表达终态。

## 6. 外部能力和智能体工作流（Agent Workflow）决策

### 6.1 条件启用

大语言模型（LLM）、文档解析器、向量检索、重排序、对象存储、消息队列和第三方平台均按当前切片的实际用途作为条件能力，不是所有后端切片的固定前置条件。

首次进入当前切片关键路径的外部能力，必须完成最小真实验证。仅有配置存在、文档阅读、模拟替身（Mock）或单元测试不构成外部能力通过证据。

### 6.2 工具和模型边界

智能体工作流（Agent Workflow）只能调用已注册、输入经过校验且边界明确的工具。模型不得拼接 SQL、Shell 命令或未经校验的外部请求；模型输出不得直接成为事实、状态变化或外部副作用指令。

## 7. 测试与端到端反馈决策

每个切片至少形成以下最小验证链：

```text
后端实现
  → 单元测试
  → 代码评审
  → 接口/集成测试
  → 真实前端接入
  → 端到端验证（End-to-End，E2E）
```

受控演示项目可以缩小测试范围，但不能以真实前端测试替代核心业务规则、资源归属、状态迁移和数据契约的最小单元测试。

端到端反馈（E2E Feedback）发现以下问题时，必须回退到对应的最早决策位置：

| 问题 | 回退位置 |
| --- | --- |
| 前端流程与当前交付范围不一致 | 版本范围裁决 |
| API 字段、状态或语义不一致 | 应用程序接口契约（API Contract） |
| 数据模型、状态机、事务或模块边界不一致 | 方案设计 |
| 外部能力方案不可用 | 外部能力预验证 |
| 任务依赖或验收拆分不成立 | 任务拆分 |

不得在前端临时增加业务规则来掩盖后端契约或领域问题。

## 8. 旧资产迁移决策

旧后端代码和文档必须先经过旧资产盘点（Legacy Asset Inventory），再决定是否进入新事实源。盘点状态固定为：

- `reusable`：有代码、测试、迁移或锁定契约证据，可复用或引用；
- `partial`：部分有效，需要按当前切片边界重写；
- `obsolete`：已失效、越界或会误导当前开发；
- `pending`：证据不足或存在冲突，等待差距分析（Gap Analysis）、契约或切片方案裁决。

旧资产不能整体复制到新目录。迁移动作只能是迁移、重写、引用、保留、归档或不迁移；历史变更包保留历史追溯价值，不直接成为新的切片任务清单。

## 9. 领域、状态和数据设计决策

领域模型、状态模型和数据库设计采用增量确认：

- 需求和范围阶段只确认业务概念、资源归属和必要状态；
- 方案阶段确认当前切片实际使用的实体、字段、状态迁移、约束和事务边界；
- 数据库设计以已执行迁移、代码模型（Model）和锁定契约为实现事实；
- 未被当前切片证明需要的实体、字段和版本能力保持延期（deferred）或待确认（pending）。

不得因为旧文档已经定义完整领域模型或数据库表，就提前实现全部模型。新增共享状态时必须明确唯一状态拥有者和跨模块交接方式。

## 10. 决策变更与回退

以下长期决策发生变化时，必须形成新的决策记录，并说明受影响的切片、契约和最低回退位置：

- 前后端协作范式或垂直切片交付方式变化；
- 应用程序接口契约（API Contract）治理方式变化；
- 分层职责、模块依赖或仓储层（Repository）数据边界变化；
- 资源归属、状态拥有者或不可降级安全边界变化；
- 外部能力启用原则、智能体工具边界或测试反馈链变化。

锁定契约不得静默修改；跨模块契约变化必须通知全部生产者、消费者和参与方，并共同重新确认。
