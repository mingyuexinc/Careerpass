# Slice：S-06 求职目标创建

> 本 Slice 关联 [`IS-S06-01`](../../../../../docs/integration/slices/slice-06-job-goal/integration-scenario.md)。S-06 定义求职目标的创建和更新边界；S-07 负责启动 Agent 时的简历绑定和启动校验。

> 当前阶段：Close

> 当前状态：前后端代码、Contract、自动化验证和真实 API 联调已完成；`IS-S06-01` 已标记为 `integration_delivered`。

## 1. 目标

求职者可以在登录后创建或更新一个当前求职目标。目标保存后，后续 Agent 流程可以读取该目标；目标配置不依赖岗位 JD 或简历是否已经完成准备。

## 2. 输入

- 已登录并经服务端确认的求职者身份。
- 目标 Offer 数量。
- 目标岗位名称。
- 可为空的岗位筛选自由文本。
- 当前求职者已有的当前目标（更新场景）。

## 3. 输出

- 当前求职者获得一个 `active` 当前求职目标。
- 已有目标时，保存结果更新同一个当前目标，不产生并行目标。
- 目标不绑定具体简历；S-07 启动 Agent 时绑定当时有效的当前简历。
- 目标保存后，前端可以重新读取并展示启动条件；启动条件不满足时不能启动 Agent。

## 4. 前置条件

- 用户已登录。
- 当前服务端身份是求职者身份。

简历解析、画像匹配资格和可用岗位 JD 不属于 S-06 的创建前置条件，由 S-07 在启动 Agent 时统一校验。

## 5. 业务规则

- 目标 Offer 数量为 1 至 10 的正整数（`BF-RULE-026`）。
- 岗位名称必填，筛选条件可为空并按自由文本保存（`BF-RULE-026`）。
- 当前版本每个求职者只维护一个当前目标（`BF-OBJECT-004`、`BF-SCOPE-004`）。
- Agent 未启动时可以更新同一个当前目标；Agent 运行中或已结束后不可修改（`BF-RULE-024`）。
- 目标创建时不绑定简历，Agent 启动时由 S-07 绑定当前简历（`BF-RULE-025`）。
- 保存目标是目标的创建或更新，不是 Agent 启动提交；重复保存不得产生第二个当前目标（`BF-RULE-027`）。
- 目标状态由 `active`、`achieved` 和 `abandoned` 表达；S-06 只创建或更新 `active`，当前版本没有用户主动放弃入口（`BF-STATE-016`）。

## 6. 范围 / 非目标

### 当前范围

- 创建当前求职目标。
- 查询当前求职目标。
- Agent 未启动前更新当前求职目标。
- 服务端校验目标归属和目标字段业务约束。

### 非目标 / 延期

- 不要求已有简历、画像或岗位 JD。
- 不绑定简历，不创建 Agent 运行或投递轮次。
- 不启动 Agent，不执行岗位匹配，不创建投递记录。
- 不解释自由文本筛选条件；筛选行为由 S-08 裁决。
- 不提供用户主动放弃目标的操作。

## 7. 技术约束

- 遵循 Repository 数据访问边界和当前求职者资源归属校验。
- API 响应遵循 `{code, msg, data}`。
- 本 Slice 不产生异步任务。
- 目标保存与 Agent 启动分属不同 Slice；S-07 负责启动时的当前简历绑定。

## 8. 验收标准

- 登录求职者可以在没有简历或岗位 JD 的情况下保存有效求职目标。
- 保存后刷新仍能读取当前目标，且目标归属于当前求职者。
- Agent 未启动时可以修改目标；修改结果仍属于同一个当前目标。
- Offer 数量为 0、负数、非整数或大于 10 时不能保存。
- 岗位名称为空时不能保存；筛选条件为空时可以保存。
- Agent 运行中或已结束后，修改目标被拒绝。
- 目标保存不会绑定简历，也不会启动 Agent。
