# Slice：S-07 Agent 投递启动

> 本 Slice 关联 [`IS-S07-01`](../../../../../docs/integration/slices/slice-07-agent-start/integration-scenario.md)。S-07 只负责启动校验、当前简历绑定和运行上下文创建；S-08 负责可用岗位检查、匹配和投递记录。

> 当前阶段：Slice Design（Contract Locked）

## 1. 目标

已登录求职者在当前求职目标、当前简历和画像条件满足时启动 Agent。系统绑定启动时有效的当前简历，创建本轮运行上下文并使 Agent 进入 `running`；页面继续展示当前用户自己的求职目标。

## 2. 输入

- 已登录并由服务端确认的求职者身份。
- 当前求职者的 `active` 求职目标。
- 当前求职者解析成功且具备匹配资格的简历画像。
- 求职者在任务页提交启动操作。

## 3. 输出

- 当前 Agent 运行上下文进入 `running`。
- 启动时有效的当前简历绑定到本轮运行上下文。
- 同一运行上下文收到重复启动请求时幂等返回，不创建新的运行上下文。
- 当前求职目标保持原有业务状态，但 Agent 运行中不可修改。
- 前端不展示匹配过程；启动完成后进入求职进度页查看 S-08 生成的投递结果、匹配得分和推荐理由。

S-07 不创建匹配结果或投递记录；这些结果由 S-08 负责。

## 4. 前置条件

- 用户已登录。
- 当前服务端身份是求职者身份。
- 当前求职目标已创建。
- 当前简历解析成功。
- 候选人画像具备岗位匹配资格。
- 当前 Agent 尚未运行或结束。

可用结构化岗位 JD 不属于 S-07 前置条件，由 S-08 在匹配前检查。

## 5. 业务规则

- 启动时绑定当前有效简历（`BF-RULE-025`）。
- Agent 启动后不能重复启动、替换本轮简历或修改当前目标（`BF-RULE-024`、`BF-STATE-003`）。
- 同一运行上下文的重复启动按幂等成功处理（`BF-RULE-028`）。
- 目标保持原有状态，达到 Offer 目标后才由后续流程转为 `achieved`（`BF-RULE-029`、`BF-STATE-016`）。
- 前端不展示匹配资格详情；未满足启动条件时统一表现为尚未启动/暂不可启动（`BF-STATE-017`）。

## 6. 范围 / 非目标

### 当前范围

- 启动条件的服务端校验。
- 当前简历与本轮运行上下文的绑定。
- 当前 Agent 运行上下文的创建、幂等复用和 `running` 状态。
- 任务页左右双栏 UI：左侧配置与启动，右侧当前目标只读查看。

### 非目标 / 延期

- 不检查可用结构化岗位 JD。
- 不执行岗位匹配。
- 不创建匹配结果或投递记录。
- 不展示匹配资格字段、缺失字段或简历画像详情。
- 不提供用户主动暂停、终止或重新开启新一轮任务。

## 7. 技术约束

- 遵循当前身份、Candidate 归属和 Repository 数据访问边界。
- 启动请求和重复请求必须由服务端决定，不由前端状态单独形成事实。
- API 响应遵循 `{code, msg, data}`。
- S-07 不直接调用外部匹配服务；S-08 负责后续岗位检查和匹配。

## 8. 验收标准

- 满足目标、简历和画像条件的求职者可以启动 Agent，页面展示运行中及约定成功文案。
- 启动后当前目标仍可查询，右侧面板展示当前用户自己的目标内容。
- 启动后当前目标不可修改，页面以只读/已锁定状态展示。
- 重复点击或重复请求不会创建第二个运行上下文。
- 启动后不产生匹配结果或投递记录；S-08 承担后续结果。
- 没有当前目标、简历未解析成功或画像条件不满足时，启动按钮不可用，页面不展示匹配资格详情。
- 没有岗位 JD 不阻止 S-07 启动；岗位检查由 S-08 负责。
