# 后端能力映射

> 文档层级：版本能力映射（Capability Map）。
>
> 文档目的：把正式前端的用户流程、页面操作和可观察结果，映射为后端需要提供的业务能力、接口类型、异步/工作流依赖、权限边界和垂直切片（Vertical Slice）候选范围。
>
> 本文档是 `backend-delivery-scope.md` 与 `backend-gap-analysis.md` 之间的中间事实源。它记录“前端需要什么后端能力以及当前证据如何”，不直接锁定 API 字段、数据库结构或实现任务。

业务目标、角色、流程、状态和跨角色规则以项目级 [`../../../docs/business/business-baseline.md`](../../../docs/business/business-baseline.md) 为准；本文档只负责后端能力映射和实现证据。

## 1. 文档定位

### 1.1 本文档回答的问题

- 正式前端的每个主流程操作需要哪些后端能力；
- 能力由同步 API、异步任务、Agent Workflow 或外部能力中的哪一类承载；
- 能力涉及哪些资源、资源所有者和权限边界；
- 当前后端是否已有代码、测试、迁移或契约证据；
- 能力依赖哪些前置能力，以及后续应进入哪个 Vertical Slice。

### 1.2 本文档不承担的职责

| 不承担的内容 | 事实源 |
| --- | --- |
| 当前版本是否交付、延期或属于非目标 | `docs/product/backend-delivery-scope.md` 和 `../../../docs/business/business-baseline.md` |
| 精确 API 路径、请求字段、响应字段和错误码 | 具体 Slice 的 `technical-design.md` |
| 异步任务的详细输入、输出、状态和失败语义 | 具体 Slice 的 `technical-design.md` |
| 完整领域实体、字段和数据库表 | `docs/domain/`、`docs/data/` |
| 详细状态迁移、业务规则和进度事件 | `docs/domain/domain-model.md`、`docs/product/business-rules.md` |
| 具体类、函数、Repository、任务和技术实现 | `docs/architecture/`、切片方案和代码 |
| 差距的解决方向和 Slice 开发顺序 | `docs/development/backend-gap-analysis.md`、`vertical-slice-plan.md` |
| MinerU、Qwen 或其他外部能力的真实验证结论 | `docs/integrations/spikes/` |

前端页面中的字段、Mock 数据和展示文案只能作为需求线索，不能单独证明后端领域字段、状态或数据表已经确定。

## 2. 映射原则

### 2.1 以用户操作为映射粒度

每一行应代表一个前端可观察的后端能力，例如“求职者上传本人简历”“HR 更新单条投递记录状态”。不要按 Python 文件、数据库表或技术层横向罗列。

一个前端页面可以对应多个能力；一个后端能力也可以被多个页面消费。只有能够说明用户结果、资源边界和证据状态时，才建立一条映射。

### 2.2 先映射版本范围，再判断当前实现

能力是否属于当前版本，以 `backend-delivery-scope.md` 为准；能力是否已实现，以代码、测试、迁移或锁定契约为证据。以下情况不能标记为已实现：

- 前端存在页面或 Mock 数据；
- 后端存在占位文档、模型草稿或旧变更包；
- 只有配置、适配器或单元测试，没有真实外部能力证据；
- 旧文档描述过实体，但当前代码和迁移没有证明它存在。

### 2.3 后端能力必须保留业务边界

每条映射至少说明：

- 当前角色和资源所有者；
- 当前用户能否读取、创建或修改该资源；
- 状态由哪个模块拥有；
- 是否产生异步任务、Agent 行为或外部副作用；
- 结果是事实、处理中状态、失败状态还是可重试操作。

### 2.4 前端不替代后端规则

前端可以提供触发场景和可观察结果，但不能决定：

- 资源的归属关系；
- 状态是否合法迁移；
- LLM 输出是否可以入库；
- 是否允许对外投递或发送消息；
- 是否需要异步任务、幂等键和审计记录。

## 3. 状态和证据分类

### 3.1 能力状态

| 状态 | 判定标准 |
| --- | --- |
| `reusable` | 当前代码、测试、迁移或锁定契约足以支撑该能力，可复用或引用。 |
| `partial` | 已存在部分实现，但缺少完整流程、角色、契约、真实外部证据或前端验收。 |
| `missing` | 当前版本需要，但未发现可支撑该能力的实现证据。 |
| `design_ready` | 业务范围、Slice 设计、接口/集成契约和验收场景已锁定，但尚未有代码实现证据。 |
| `conditional` | 只有在某个具体 Slice 使用时才启用，例如异步、Agent 或外部服务。 |
| `deferred` | 已由版本范围明确延期，不进入当前版本开发前置条件。 |
| `pending` | 角色、范围、资源、状态或依赖仍存在冲突，暂不能裁决。 |

### 3.2 证据等级

| 证据 | 说明 |
| --- | --- |
| `code` | 当前正式后端代码存在对应公开能力或完整调用链。 |
| `test` | 有与该能力边界相符的单元、接口、集成或端到端测试。 |
| `migration` | 数据结构已经由当前 Alembic 迁移证明。 |
| `contract` | 有已锁定的 API 或异步契约，并明确参与方。 |
| `external-validation` | 外部能力有受控真实验证记录。 |
| `frontend-only` | 只有前端页面或 Mock 证据，不能作为后端实现证据。 |
| `none` | 尚未发现有效证据。 |

测试通过只证明测试覆盖范围内的行为，不自动证明完整前端能力、真实外部拓扑或生产部署能力。

## 4. 当前版本前端流程索引

以下流程来自正式前端的验收流程和产品流程；这里只建立后端映射入口，不重新定义前端页面事实。

| 流程编号 | 角色 | 前端流程 | 主要可观察结果 |
| --- | --- | --- | --- |
| F-01 | 公共 | 选择求职者或 HR 身份并登录 | 进入对应角色工作区，角色菜单隔离 |
| F-02 | 求职者 | 上传、查看和删除简历及其他求职资料 | 简历进入解析流程，资料按删除条件从当前可用列表移除 |
| F-03 | 求职者 | 查看简历解析结果 | 看到解析中、成功或失败状态；画像匹配资格由后端用于启动校验，不向页面展示详情 |
| F-04 | 求职者 | 创建求职目标 | 目标保存，启动条件重新计算 |
| F-05 | 求职者 | 满足条件后启动 Agent | 只有当前目标已创建、简历解析成功且画像具备匹配资格时，S-07 才绑定当前简历并使 Agent 进入运行中；不能重复启动或替换当前绑定简历；可用结构化 JD 由 S-08 在匹配前检查 |
| F-06 | 求职者 | 查看投递轮次和进度看板 | 看到空状态、投递记录、岗位阶段和 Offer 指标 |
| F-07 | HR | 上传、查看和删除岗位 JD | 系统具备可用于当前演示的岗位数据，已删除岗位不再作为当前可用岗位 |
| F-08 | HR | 查看岗位下的沟通 | 看到授权范围内的完整会话和消息 |
| F-09 | HR | 发送消息并获得系统回复 | 消息经历发送中、回复中、成功或失败状态 |
| F-10 | HR | 修改单条投递记录状态 | 合法推进当前岗位下当前候选人的一条投递记录 |
| F-11 | 双方 | 状态变化后刷新相关页面 | 求职者和 HR 看到各自允许范围内的一致结果 |

当前版本不把真实招聘平台投递、真实外部消息、多轮投递、实时推送和生产级调度作为隐含后端能力。

## 7. 能力依赖关系

当前版本的最小业务依赖关系为：

```text
认证与角色
  ├─> 求职者资料 ─> 简历解析与画像 ──┐
  ├─> 求职目标（可并行配置） ────────┼─> 启动条件
  └─> HR 岗位 JD ─> 可用岗位 ────────┘
                                      └─> Agent 任务
                                              ├─> 匹配结果
                                              └─> 投递记录
                                                      ├─> 求职者进度看板
                                                      ├─> HR 投递进度管理
                                                      └─> 沟通会话与消息
```

依赖关系只说明能力进入下一阶段所需的前置条件，不提前确定数据库外键、事务边界、Celery 编排或具体实现方式。

## 8. 垂直切片归属规则

能力进入具体 Slice 前，必须补充并确认：

- 前端触发场景和用户可观察结果；
- 当前版本内的必须交付和明确不做；
- 输入、输出、资源所有者和授权范围；
- API Contract、数据变化和状态变化；
- 异步任务、Agent、外部能力和副作用；
- 单元、接口、集成和真实前端验收标准。

推荐的 Slice 能力边界如下：

| Slice 候选 | 最小能力范围 | 不自动包含 |
| --- | --- | --- |
| 基础身份 | 登录、当前身份、角色访问边界 | 复杂注册和多租户账号体系 |
| JD 准备 | HR 上传受控岗位 JD、岗位可用性 | 公开网络爬取、复杂岗位目录 |
| 资料和解析 | 简历/资料上传、解析状态、画像读取 | 生产级文件中心和无限制资料管理 |
| 求职目标与启动 | 目标保存、启动条件、幂等任务入口 | 多目标、多轮投递和用户主动终止 |
| 匹配与投递 | 受控岗位匹配、首轮系统内投递记录 | 真实外部投递和完整自动调度 |
| 进度与沟通 | 投递状态查询/合法更新、系统内会话 | 实时推送、真实外部消息 |

表中的 Slice 名称只是规划边界，正式顺序和依赖由 `vertical-slice-plan.md` 在 Gap Analysis 完成后裁决。

## 9. 未决事项和回退规则

以下事项不能由本文件自行猜测：

| 未决事项 | 影响 | 后续裁决位置 |
| --- | --- | --- |
| User/Candidate 与 HR 身份的正式关系 | 认证、资源归属和 HR 查询权限 | 认证 Contract / 领域模型 |
| 求职目标的资源和状态拥有者 | 目标归属于 Candidate；S-06 拥有创建/更新边界；S-07 拥有启动时校验、运行冻结和简历绑定 | S-06 Slice Design / 技术设计 |
| 岗位 JD 的结构化解析方式 | 固定 Markdown 标题、五项核心字段、额外字段和失败边界已实现；真实 Compose 拓扑与 `IS-S03-01` 已通过 | S-03 Technical Design / Readiness Check |
| 匹配结果的算法版本、字段结构和历史版本表达 | 匹配查询、重复执行和投递幂等 | S-08 数据设计 / API Contract |
| Agent 回复是否允许使用真实模型 | 授权、脱敏、超时、审计和失败语义 | Agent 架构 / 外部能力 Spike |
| 投递状态事件和 Offer 达标判定 | 状态机、Progress Event 和任务终态 | `business-rules.md` / `domain-model.md` |

如果真实前端接入发现以下问题，应回退到最早的对应文档：

| 发现的问题 | 回退位置 |
| --- | --- |
| 前端流程不属于当前版本范围 | `backend-delivery-scope.md` |
| 能力缺少或误映射 | 本文档和 `backend-gap-analysis.md` |
| API 字段、状态或语义不一致 | 对应 Slice 的 `technical-design.md`，并回退 Slice Design |
| 资源归属、状态或事务边界不一致 | 领域、状态或切片方案 |
| 外部能力不可用 | `integrations/spikes/` |
