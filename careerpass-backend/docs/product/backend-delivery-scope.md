# 后端当前版本交付范围

> 范围层级：一级范围（Release Scope）。
>
> 文档目的：定义当前后端版本交付什么以及延期什么。
>
> 本文件不定义单个垂直切片（Vertical Slice）的字段、接口、数据表、任务或实现方案；这些内容由二级切片范围（Slice Scope）和三级实现细节（Implementation Detail）负责。
>
> 版本性质：受控演示项目（Demo）的后端版本，不是公开运营或生产级平台。

## 1. 范围层级和使用规则

当前后端采用三级范围：

| 层级 | 文档位置 | 负责内容 |
| --- | --- | --- |
| 一级范围（Release Scope） | 本文件 | 版本目标、核心闭环、能力级本期范围和延期能力 |
| 二级切片范围（Slice Scope） | `docs/development/slices/<slice>/slice-spec.md` | 当前切片的用户场景、边界、输入输出、依赖和切片级验收 |
| 三级实现细节（Implementation Detail） | 切片方案、任务、代码和测试文档 | API 字段、表结构、函数、任务、技术选型和实现过程 |

使用规则：

- 二级切片范围只能选择和细化一级范围，不能无授权扩大版本目标；
- 三级实现细节可以在开发中调整，但不能改变已裁决的用户行为、授权、资源归属或外部副作用；
- 若实现发现改变当前切片用户行为，必须回到二级切片范围；
- 若新增版本能力、用户角色、核心闭环或外部副作用，必须回到一级范围重新裁决；
- 未列入本文件的能力，默认不属于当前版本，除非完成正式范围变更。

## 2. 当前版本目标

当前版本验证一个由求职者和 HR 共同参与的、可重复演示的系统内求职闭环。

### 2.1 求职者演示流程

```text
求职者登录
  → 上传简历并获得可用画像
  → 创建求职目标
  → 使用可用岗位进行匹配
  → 查看系统内投递记录和求职进度
  → 查看系统内沟通结果
```

### 2.2 HR 演示流程

```text
HR 登录
  → 提供受控岗位 JD
  → 查看允许范围内的投递和沟通信息
  → 更新单条投递记录的求职进度
```

### 2.3 双方协作结果

```text
HR 提供岗位和进度变化
  → 系统形成匹配、投递和沟通记录
  → 求职者看到与本人相关的进度结果
```

版本完成的判断依据是：求职者和 HR 均能通过正式前端完成各自的受控流程，并获得可观察、可解释、可重复的系统内结果；不是后端已经具备未来生产运营所需的全部平台能力。

## 3. 目标用户和运行边界

### 3.1 目标用户

- 开发者本人或受控演示用户；
- 求职者角色：仅负责上传本人简历和创建求职目标；可查看系统生成的匹配结果、投递记录和沟通内容，但不负责管理这些结果或内容；
- 人力资源角色（HR）：在系统内提供受控岗位数据、查看允许范围内的沟通内容并更新投递进度；
- 系统职责：根据候选人画像和求职目标生成匹配结果，创建和维护投递记录，生成和维护系统内沟通内容；
- 智能体（Agent）：执行已授权的系统内匹配、沟通草稿或模拟流程，不直接产生真实外部副作用。

### 3.2 运行和数据边界

- 使用受控测试环境，不面向公开用户、高并发或多租户运营；
- 仅使用测试人员准备的脱敏数据，不在系统中引入不必要的真实身份信息和联系方式；
- 岗位数据来自受控输入或测试数据，不依赖公开网络爬取和第三方平台同步；
- 投递、沟通和进度只在系统内模拟或记录，不向真实招聘平台或真实招聘方发送内容；
- 任何用户资源仍必须执行当前用户和资源归属校验，不因受控演示而绕过权限边界。

## 4. 本期范围（In Scope）

本节只列版本级能力，不定义接口、字段、数据库表或具体实现方式。

### 4.1 求职者能力范围

本表仅记录求职者执行的用户动作；匹配、投递、沟通及其状态维护由系统负责，不列为求职者的管理能力。

| 能力（动作） | 本版本交付目标 |
| --- | --- |
| 登录并建立求职者身份 | 支持受控求职者登录，并建立后续业务流程所需的可信当前身份。 |
| 上传本人正式简历 | 支持求职者上传本人正式简历，并获得资料处理结果。 |
| 创建求职目标 | 支持求职者创建并保存当前求职目标。 |
| 查看系统生成的岗位匹配结果 | 支持求职者查看基于本人画像、目标和可用岗位形成的结构化、可解释匹配结果。 |
| 查看系统内投递记录 | 支持求职者查看与本人相关的系统内投递记录。 |
| 查看投递进度 | 支持求职者查看本人投递记录的招聘进度。 |
| 查看系统内沟通结果 | 支持求职者查看与本人投递相关的系统内沟通结果。 |

### 4.2 HR 能力范围

| 能力（动作） | 本版本交付目标 |
| --- | --- |
| 登录并建立 HR 身份 | 支持受控 HR 登录，并进入 HR 对应的业务工作区。 |
| 提供岗位 JD | 支持 HR 或受控测试流程提供岗位 JD，使其成为后续流程可使用的岗位信息。 |
| 查看允许范围内的投递信息 | 支持 HR 查看允许范围内的岗位和投递信息。 |
| 查看允许范围内的沟通信息 | 支持 HR 查看允许范围内的系统内沟通记录。 |
| 更新投递进度 | 支持 HR 更新单条投递记录的求职进度。 |

### 4.3 双方共享与系统协作能力

| 能力（动作） | 本版本交付目标 |
| --- | --- |
| 解析简历并生成候选人画像 | 系统将受控简历处理为后续求职流程可使用的结构化候选人画像。 |
| 生成岗位匹配结果 | 系统根据候选人画像、求职目标和可用岗位生成结构化、可解释的匹配结果。 |
| 创建系统内投递记录 | 系统根据候选人、岗位、目标和可选匹配结果创建系统内投递记录。 |
| 创建系统内沟通并生成回复 | 系统基于已授权上下文创建沟通记录，并生成系统内回复草稿或模拟回复。 |
| 通过后端契约完成前端闭环接入 | 正式前端可以调用已锁定的后端契约，完成求职者和 HR 各自的当前版本流程。 |

本节只确认能力是否属于当前版本。每项能力的具体切片边界、前置条件、接口和数据结构由对应切片范围文档另行裁决。

## 5. 延期能力（Deferred）

以下能力可以保留设计线索，但不得作为当前版本的实现前置条件、切片验收条件或发布阻塞项。每一行仅填写一项延期能力；延期理由、重新评估条件、对当前版本范围/验收的影响和开发者裁决均由开发者单独填写。

| 编号 | 类别 | 延期能力 | 开发者裁决 |
| --- | --- | --- | --- |
| 1 | 账号体系 | 用户注册 | 用户注册不属于Demo演示必须展示的内容 |
| 2 | 工作流 | 多轮岗位匹配和投递 | Demo演示出于演示效率和必要性，暂时延期 |

延期不代表已经设计完成，也不代表未来一定实现；它只表示本版本暂不处理该能力。

## 6. 版本级成功标准

当前版本满足以下用户可观察结果时，视为达到版本范围目标：

1. 受控用户可以登录并进入对应业务工作区；
2. 求职者可以上传简历并看到可供后续流程使用的解析结果；
3. 求职者可以创建求职目标；
4. 系统可以使用可用岗位、候选人画像和求职目标形成可解释的匹配结果；
5. 系统可以创建投递记录并展示其进度；
6. 系统可以在授权范围内创建系统内沟通并显示回复草稿或模拟回复；
7. 正式前端可以通过锁定的应用程序接口契约（API Contract）完成核心路径；
8. 以上结果不产生真实外部投递、外部消息或未经授权的不可逆副作用。

这些是版本级用户结果，不替代切片级测试、接口验证、代码评审和端到端验收标准。

## 7. 与二级、三级范围的关系

### 7.1 二级切片范围（Slice Scope）

每个切片必须从本文件选择明确的版本能力，并补充：

- 当前前端触发场景；
- 本切片的输入、输出和用户可见结果；
- 本切片涉及的资源、状态和授权；
- 当前切片依赖的已有后端能力；
- 切片级延期能力（如有）；
- 切片级契约、方案和验收标准。

切片不能把本文件中的多个能力未经拆分地直接当作一个实现任务，也不能将延期能力作为隐含前置条件。

### 7.2 三级实现细节（Implementation Detail）

实现阶段可以继续发现和调整：

- 具体类、函数、模块和目录；
- API 字段的具体类型和校验实现；
- 数据库索引、约束和迁移脚本；
- 异步任务内部编排、日志字段和测试替身；
- 外部客户端适配细节。

只要不改变版本范围、切片用户行为、资源归属、状态拥有者和外部副作用，上述调整不需要修改本文件。

## 8. 范围变更规则

出现以下变化时，必须回到相应范围层级重新裁决：

| 变化 | 回退层级 |
| --- | --- |
| 内部实现、函数、索引或测试组织调整，不改变用户行为 | 三级实现细节（Implementation Detail）内部处理 |
| 当前切片新增或删除用户操作、资源、状态或接口行为 | 二级切片范围（Slice Scope） |
| 新增版本能力、用户角色、核心闭环或外部副作用 | 一级范围（Release Scope） |
| 将延期能力提前纳入当前版本 | 一级范围（Release Scope），并更新延期清单和影响分析 |

任何未完成范围裁决的新增能力，都不得通过“先实现、之后补文档”进入当前版本。
