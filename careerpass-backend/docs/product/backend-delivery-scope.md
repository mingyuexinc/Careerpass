# 后端当前版本交付范围

> 范围层级：一级范围（Release Scope）。
>
> 文档目的：定义当前后端版本交付什么以及延期什么。
>
> 本文件不定义单个垂直切片（Vertical Slice）的字段、接口、数据表、任务或实现方案；这些内容由二级切片范围（Slice Scope）和三级实现细节（Implementation Detail）负责。
>
> 版本性质：受控演示项目（Demo）的后端版本，不是公开运营或生产级平台。

跨前后端共享的产品目标、角色、流程、范围和业务规则以项目级 [`../../../docs/business/business-baseline.md`](../../../docs/business/business-baseline.md) 为共同基线；本文档负责后端版本范围和延期能力，不重复定义业务事实。

## 1. 范围层级和使用规则

当前后端采用三级范围：

| 层级 | 文档位置 | 负责内容 |
| --- | --- | --- |
| 一级范围（Release Scope） | 本文件 | 版本目标、核心闭环、能力级本期范围和延期能力 |
| 二级切片范围（Slice Scope） | `docs/development/slices/<slice>/slice-spec.md` | 当前切片的用户场景、边界、输入输出、依赖和切片级验收 |
| 三级实现细节（Implementation Detail） | 切片方案、任务、代码和测试文档 | API 字段、表结构、函数、任务、技术选型和实现过程 |

使用规则：

- 二级切片范围只能选择和细化一级范围，不能无授权扩大版本目标；
- 三级实现细节可以在开发中调整，但不能改变已裁决的用户行为、授权、资源归属或外部副作用；
- 若实现发现改变当前切片用户行为，必须回到二级切片范围；
- 若新增版本能力、用户角色、核心闭环或外部副作用，必须回到一级范围重新裁决；
- 未列入本文件的能力，默认不属于当前版本，除非完成正式范围变更。

## 2. 当前版本目标

当前版本验证一个由求职者和 HR 共同参与的、可重复演示的系统内求职闭环。

### 2.1 求职者演示流程

```text
求职者登录
  → 上传 PDF 简历并获得解析结果和匹配资格
  → 上传求职者资料
  → 创建求职目标
  → 满足匹配资格后启动 Agent 并使用可用岗位进行匹配
  → 查看求职进度
```

### 2.2 HR 演示流程

```text
HR 登录
  → 提供受控岗位 JD
  → 查看岗位投递和沟通信息
  → 更新单条投递记录的求职进度
```

### 2.3 双方协作结果

```text
HR 提供岗位和进度变化
  → 系统形成匹配、投递和沟通记录
  → 求职者看到与本人相关的进度结果
```

版本完成的判断依据是：求职者和 HR 均能通过正式前端完成各自的受控流程，并获得可观察、可解释、可重复的系统内结果；不是后端已经具备未来生产运营所需的全部平台能力。

## 3. 目标用户和运行边界

### 3.1 目标用户

- 开发者本人或受控演示用户；
- 求职者角色：负责上传本人简历、求职者资料和创建求职目标；可查看系统生成的匹配结果和求职进度，不提供系统内沟通内容查看能力；
- 人力资源角色（HR）：在系统内提供受控岗位数据、查看岗位投递和沟通内容并更新投递进度；
- 系统职责：根据候选人画像和求职目标生成匹配结果，创建和维护投递记录，生成和维护系统内沟通内容；
- 智能体（Agent）：执行已授权的系统内匹配、沟通草稿或模拟流程，不直接产生真实外部副作用。

### 3.2 运行和数据边界

- 使用受控测试环境，不面向公开用户、高并发或多租户运营；
- 仅使用测试人员准备的脱敏数据，不在系统中引入不必要的真实身份信息和联系方式；
- 岗位数据来自受控输入或测试数据，不依赖公开网络爬取和第三方平台同步；
- 当前演示正式简历只接受文本型 PDF；不处理其他格式、扫描件、图片型 PDF、加密 PDF 或密码保护 PDF；
- 当前演示岗位 JD 来自构造的 Markdown 数据，一份文件对应一份岗位，数据保证岗位匹配所需的五项核心字段有效；
- 投递、沟通和进度只在系统内模拟或记录，不向真实招聘平台或真实招聘方发送内容；
- 任何用户资源仍必须执行当前用户和资源归属校验，不因受控演示而绕过权限边界。

### 3.3 受控演示账号

当前版本不提供用户注册流程。为保证正式前端可以重复演示登录和双角色流程，演示环境必须通过幂等初始化流程预置以下两个账号：

| 身份 | 用户名 | 密码 | 业务身份 |
| --- | --- | --- | --- |
| 求职者 | `candidate_01` | `123` | Candidate |
| HR | `hr_01` | `123` | HrProfile |

约束：

- 两个账号各一个即可覆盖当前版本演示目标，不扩展多账号、多租户或注册能力。
- 初始化流程负责创建或复用 User、角色关联和对应的 Candidate/HrProfile 身份，重复执行不得创建重复账号。
- 密码只用于受控演示环境的初始化和登录验证，不得进入 API 响应、日志、追踪或生产环境配置。
- 演示账号不代表公开用户账号体系；新增账号仍不属于当前版本范围。

## 4. 本期范围

本节只列版本级能力，不定义接口、字段、数据库表或具体实现方式。

### 4.1 求职者能力范围

本表仅记录求职者执行的用户动作；匹配、投递、沟通及其状态维护由系统负责，不列为求职者的管理能力。

| 能力（动作） | 本版本交付目标 |
| --- | --- |
| 登录并建立求职者身份 | 支持受控求职者登录，并建立后续业务流程所需的可信当前身份。 |
| 上传本人正式简历 | 支持求职者上传 PDF 格式正式简历，并获得上传、解析和匹配资格处理结果。 |
| 上传求职者资料 | 支持求职者上传并保存其它求职资料。 |
| 删除简历和求职者资料 | 支持求职者删除简历或求职者资料；具体删除条件、引用影响和对象处理按资源类型执行。 |
| 创建求职目标 | 支持求职者创建并保存当前求职目标。 |
| 查看系统生成的岗位匹配结果 | 支持具备匹配资格的求职者在投递记录中查看基于本人画像、目标和可用岗位形成的推荐匹配得分与推荐理由；未形成投递记录的 Match 不在进度页展示。 |
| 查看求职进度 | 支持求职者在求职进度页面查看本人投递记录、招聘阶段和进度结果。 |

### 4.2 HR 能力范围

| 能力（动作） | 本版本交付目标 |
| --- | --- |
| 登录并建立 HR 身份 | 支持受控 HR 登录，并进入 HR 对应的业务工作区。 |
| 提供岗位 JD | 支持 HR 或受控测试流程提供岗位 JD，使其成为后续流程可使用的岗位信息。 |
| 删除岗位 JD | 支持 HR 删除岗位 JD；删除条件和已被下游业务引用时的处理方式按岗位资源规则执行。 |
| 查看岗位投递信息 | 支持 HR 查看岗位投递信息。 |
| 查看岗位沟通信息 | 支持 HR 查看岗位沟通记录。 |
| 更新投递进度 | 支持 HR 更新单条投递记录的求职进度。 |

### 4.3 系统能力

| 能力（动作） | 本版本交付目标 |
| --- | --- |
| 解析简历并生成候选人画像 | 系统将受控 PDF 简历处理为结构化候选人画像，并独立判断画像是否具备岗位匹配资格；解析成功但业务字段不完整时，不得启动 Agent。 |
| 生成岗位匹配结果 | 系统使用本地简化算法，根据具备匹配资格的候选人画像、求职目标和构造岗位逐个筛选并生成结果；允许本轮 Application 数量为 0，不依赖外部匹配服务。 |
| 创建系统内投递记录 | 系统根据候选人、岗位、目标和可选匹配结果创建系统内投递记录。 |
| 创建系统内沟通并生成回复 | 系统基于已授权上下文创建沟通记录，并生成系统内回复草稿或模拟回复。 |
| 通过后端契约完成前端闭环接入 | 正式前端可以调用已锁定的后端契约，完成求职者和 HR 各自的当前版本流程。 |

本节只确认能力是否属于当前版本。每项能力的具体切片边界、前置条件、接口和数据结构由对应切片范围文档另行裁决。

## 5. 延期能力

以下能力可以保留设计线索，但不得作为当前版本的实现前置条件、切片验收条件或发布阻塞项。延期能力按以下层级记录：

- 能力级：独立的用户或系统能力，例如用户注册；
- 业务边界级：业务规则、业务范围或跨主体语义，例如跨 HR 的相同 JD 去重；
- 工程边界级：实现阶段的技术参数、并发控制、重试策略等细节，例如重试次数和退避参数。

本表只记录能力级和业务边界级延期；工程边界级延期不进入本文件，由实现设计、代码评审或疑难问题文档按需记录。每一行仅填写一项延期能力；延期理由、重新评估条件、对当前版本范围/验收的影响和开发者裁决均由开发者单独填写。

| 编号 | 层级 | 类别 | 延期能力 | 开发者裁决 |
| --- | --- | --- | --- | --- |
| 1 | 能力级 | 账号体系 | 用户注册 | 用户注册不属于 Demo 演示必须展示的内容；当前版本使用受控演示账号初始化 |
| 2 | 能力级 | 账号体系 | 用户退出 | Demo演示中，退出由前端实现本地退出，后端不负责 |
| 3 | 能力级 | 岗位 JD 上传 | 上传失败处理与失败恢复流程 | 岗位 JD 上传属于 HR 侧数据准备的前置环节；受控 Demo 只验证上传成功路径，暂不将上传失败、失败展示和失败恢复纳入当前版本验收。 |
| 4 | 业务边界级 | 岗位 JD 上传 | 不同 HR 相同内容的跨用户去重 | 当前 Demo 只处理同一 HrProfile 范围内的重复上传；跨 HR 的内容复用和归属语义暂不纳入版本验收 |
| 5 | 能力级 | 工作流 | 多轮岗位匹配和投递 | Demo演示出于演示效率和必要性，暂时延期 |
| 6 | 能力级 | 简历解析 | 非 PDF 简历格式及扫描件、图片型 PDF、加密或密码保护 PDF 的处理 | 当前版本只验证文本型 PDF；格式扩展、OCR 和受保护文件处理延期，不作为 S-04 前置条件。 |
| 7 | 业务边界级 | 岗位 JD 解析 | 真实来源 JD 的结构异常和复杂质量校验处理 | 当前演示使用结构清晰的 Markdown；核心字段缺失按解析失败且 `matching_not_ready` 处理，不保留快照；结构校验失败不纳入当前版本。 |
| 8 | 能力级 | 岗位匹配 | 外部匹配服务、向量召回、重排序和复杂匹配算法 | 当前版本使用本地简化算法；外部服务和复杂算法不作为当前版本依赖。 |
| 9 | 能力级 | 匹配结果 | 可配置的结果数量、排序和展示范围 | 当前版本逐个筛选最多 20 个岗位；Match 独立持久化，求职进度页只展示已形成投递记录的结果。 |
| 10 | 能力级 | 岗位 JD 解析 | 大模型语义解析，包括长文本摘要、职位同义归一和其他模型生成的语义扩展 | 当前版本不实现大模型语义解析；S-03 只交付经过 Schema 和业务规则校验的结构化 `fields`，原文保真和确定性归一化按 S-03 Contract 执行。 |

延期不代表已经设计完成，也不代表未来一定实现；它只表示本版本暂不处理该能力。

## 6. 版本级成功标准

当前版本满足以下用户可观察结果时，视为达到版本范围目标：

1. 受控用户可以登录并进入对应业务工作区；
2. 求职者可以上传 PDF 简历并看到解析结果和匹配资格；业务字段不完整时不能启动 Agent；
3. 求职者可以创建求职目标；
4. 具备匹配资格的求职者可以使用构造岗位、候选人画像和求职目标形成可解释的匹配结果；
5. 系统可以创建投递记录并展示其进度；
6. 系统可以在授权范围内创建系统内沟通并显示回复草稿或模拟回复；
7. 求职者和 HR 可以在各自权限范围内删除可删除的简历、求职资料或岗位 JD；
8. 正式前端可以通过锁定的应用程序接口契约（API Contract）完成核心路径；
9. 以上结果不产生真实外部投递、外部消息或未经授权的不可逆副作用。

这些是版本级用户结果，不替代切片级测试、接口验证、代码评审和端到端验收标准。

## 7. 与二级、三级范围的关系

### 7.1 二级切片范围

每个切片必须从本文件选择明确的版本能力，并补充：

- 当前前端触发场景；
- 本切片的输入、输出和用户可见结果；
- 本切片涉及的资源、状态和授权；
- 当前切片依赖的已有后端能力；
- 切片级延期能力（如有）；
- 切片级契约、方案和验收标准。

切片不能把本文件中的多个能力未经拆分地直接当作一个实现任务，也不能将延期能力作为隐含前置条件。

### 7.2 三级实现细节

实现阶段可以继续发现和调整：

- 具体类、函数、模块和目录；
- API 字段的具体类型和校验实现；
- 数据库索引、约束和迁移脚本；
- 异步任务内部编排、日志字段和测试替身；
- 外部客户端适配细节。

只要不改变版本范围、切片用户行为、资源归属、状态拥有者和外部副作用，上述调整不需要修改本文件。

## 8. 范围变更规则

出现以下变化时，必须回到相应范围层级重新裁决：

| 变化 | 回退层级 |
| --- | --- |
| 内部实现、函数、索引或测试组织调整，不改变用户行为 | 三级实现细节（Implementation Detail）内部处理 |
| 当前切片新增或删除用户操作、资源、状态或接口行为 | 二级切片范围（Slice Scope） |
| 新增版本能力、用户角色、核心闭环或外部副作用 | 一级范围（Release Scope） |
| 将延期能力提前纳入当前版本 | 一级范围（Release Scope），并更新延期清单和影响分析 |

任何未完成范围裁决的新增能力，都不得通过“先实现、之后补文档”进入当前版本。
