# Agent 工作流架构

> 当前后端尚未实现 Agent 或 Workflow 运行模块。本文档只记录启用条件和不可违反的架构边界，不声明能力已经可用。

## 1. 启用条件

Agent 工作流只能在具体 Slice 同时满足以下条件时启用：

- 前端触发、用户目标和可观察结果已经明确；
- 固定业务流程无法以普通 Service 更简单地完成；
- 可调用工具、输入 Schema、授权和副作用边界已经锁定；
- 使用的 LLM 或检索能力已在 Readiness Check 中取得真实证据；
- 运行状态、失败终态和审计要求已经进入 Slice 契约。

未满足条件时，Slice 使用普通 Service 或固定任务流程，不预建通用 Agent 平台。

## 2. 责任边界

- Agent 只生成结构化计划和选择已注册 Workflow，不直接写业务数据。
- Workflow 执行代码定义的步骤，通过 Service 调用业务能力。
- Tool 只暴露固定名称和经过 Pydantic 校验的输入，不暴露 ORM Session、Repository 实现或任意网络客户端。
- Service 负责业务规则、权限复核和事务协调。
- Repository 仍是所有持久化访问的唯一入口。

## 3. 状态与副作用

Agent 编排状态不等于 Celery 任务状态，也不直接成为业务资源状态。状态拥有者和跨模块 Handoff 必须在具体 Slice 中唯一确定。

模型输出不得直接触发投递、真实消息、状态迁移或其他不可逆副作用；结构化校验、业务校验、明确授权和审计记录缺一不可。

## 4. 安全与观测

Prompt、日志和追踪只包含任务所需的最小脱敏数据。不得记录简历原文、联系方式、凭证、内部路径、模型原始响应或工具内部异常。
