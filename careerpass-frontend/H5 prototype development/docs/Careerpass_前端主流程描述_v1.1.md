

# 前端流程描述

## 形态概述

- 整个前端页面为仿Codex页面布局，左侧为侧边栏，右侧为真正的展示页面
- 点击侧边栏中的某个菜单选项，即进入该菜单对应的页面

## 主演示流程

- 求职者侧

```txt
1.求职者身份登录
2.上传求职者资料
3.创建求职目标
4.启动求职Agent
5.Agent自动匹配并投递岗位
6.查看求职进度
7.Agent持续推进
8.达成目标Offer数量
```

- HR侧

```txt
1.HR身份登录
2.上传岗位JD资料
3.通过对话聊天窗口与求职者（Agent）就投递的岗位进行沟通交流
4.根据实际情况修改该投递岗位的求职进度
```

- Agent系统（后台部分）

```txt
用户启动求职 Agent
        ↓
Agent 执行岗位匹配与自动投递
        ↓
Agent 与 HR 自动沟通并持续更新求职进度
        ↓
系统检查当前获得的 Offer 数量
        ↓
是否达到目标 Offer 数？
   ├─ 否：自动发起下一轮岗位匹配与投递
   └─ 是：停止新增投递，求职目标标记为已完成
```



## 全局流程控制规则

- 主演示流程中，先登录HR系统，完成岗位JD上传，再开始求职者侧的演示流程（否则岗位JD数据没录入系统）
- 登录页面可以点击选项卡切换求职者/HR身份登录，即两者共用一个前端系统
- 简历解析成功&求职目标创建后才能启动Agent

## 原型演示范围与通用实践约定

### 最小可演示原则

- 本文档的主要目标是生成可重复演示的、支持基本交互的 HTML 原型，不以实现真实生产能力为目标。
- 主演示只验证以下闭环：HR 预先上传岗位 JD；求职者登录、上传简历、创建求职目标并启动 Agent；求职者查看投递进度；HR 与求职者 Agent 沟通并修改指定投递记录的求职进度。
- Agent 的岗位匹配、岗位投递、后台消息处理和进度同步均使用受控 Demo 数据或模拟结果。前端不展示岗位匹配和岗位投递过程，也不要求实现真实 Agent 调度、实时推送或后端接口。
- 启动 Agent 后不默认生成投递记录。只有存在已开启的投递轮次时，进度看板才展示投递记录；投递轮次为 0 时展示“暂无投递记录”或等价空状态。
- 本演示可以使用固定账号、固定岗位、固定候选人和固定消息作为初始数据；页面应提供足以完成主流程的成功、空状态、加载中、失败和禁用状态。
- 注册、账号校验、文件格式校验、文件大小校验、重复文件检测、真实文件上传和真实简历解析可以作为主流程之外的扩展页面或扩展交互，不得成为主演示的必要前置条件。

### 通用实践原则

- 页面仍应遵循常见 Web 交互约定：按钮具备明确的可用/禁用状态，操作后给出成功或失败反馈，加载和异步处理期间避免重复提交，空数据时展示可理解的空状态。
- 页面文案、页面标题、侧边栏菜单和状态名称应与本文档及后端 `delivery_progress_enum` 保持一致；如果为演示目的使用更易懂的中文文案，应保留明确的枚举映射。
- 涉及投递进度的修改对象统一为“某个岗位下的某个候选人的一条投递记录”，不得将状态修改为候选人全局状态或岗位全局状态。
- 本文档中超出最小演示范围的流程（例如注册、登录错误提示和扩展校验）可以保留，用于体现通用产品实践；这些流程必须标注为“非主流程”或“可选扩展”，不得与主流程的固定 Demo 规则冲突。

### Demo 数据与状态约定

- 主演示至少准备一个已上传的岗位 JD、一个求职者、一个求职目标和一组可选的投递记录；是否展示投递记录取决于当前投递轮次是否大于 0。
- 投递轮次为 0 时，求职者进度看板展示空状态，不展示虚构的岗位进度；投递轮次大于 0 时，展示该轮次产生的投递记录。
- 投递进度状态使用后端定义的枚举：`submitted`、`screening`、`written_test`、`interview_1`、`interview_2`、`interview_3`、`hr_interview`、`offer`、`terminated`。
- 页面显示文案可分别映射为“已投递、初筛中、笔试、一面、二面、三面、HR 面、获得 Offer、流程终止”。`terminated` 是否进一步显示为“被拒绝”，由 Demo 数据和文案约定决定，不得无说明地混用。
- HR 投递进度页按岗位归类展示投递记录；每条记录至少包含岗位、候选人和当前进度。状态下拉框只修改当前岗位下当前候选人的投递记录。

# 产品规则

- 注册页面不纳入主演示流程，但仍可生成对应的静态前端页面；注册交互、账号校验和后端接口属于可选扩展，不作为主演示的必要前置条件。
- 求职目标与简历的对应为一对一的关系。在数据库中有对应的字段描述
- 用户可以上传多份简历。但是本演示场景规定：不考虑上传多份简历、生成多个求职目标的情况
- 求职者上传的资料，分为简历和其它文件，两者的区别是：简历除了上传还有解析的环节，其它文件只有上传，没有解析
- 求职者资料上传环节，规定每次只能上传一份资料
- AI求职沟通只在HR侧进行展示，会线上完整的消息记录
- 用户侧不展示/查看单个岗位的沟通摘要，但会展示沟通状态信息
- 本演示场景暂时不考虑暂停/终止Agent
- 本演示流程，如果投递的岗位流程结束/被拒绝仍长期保留在看板中
- 本演示流程仅考虑单轮的投递轮次，不考虑多轮
- 本演示流程暂不考虑无可投递岗位但尚未达到目标 Offer 数量的情况
