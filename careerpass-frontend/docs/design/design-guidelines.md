# Careerpass 前端 UI/UX 设计规范

> 版本：v0.1
>
> 适用范围：正式前端 MVP
>
> 视觉基准：`prototypes/html-reference/index.html`

## 1. 文档定位

本文档将 Careerpass HTML 原型中的视觉效果和交互表达整理为正式前端可复用的 UI/UX 规范。

本文档关注：

- 整体视觉风格
- 页面布局和信息层级
- 颜色、字体、间距、圆角和阴影
- 上传、进度、状态、聊天和空状态组件
- 参考图片的使用边界
- 响应式和可访问性要求

具体页面职责见 `docs/product/frontend-product-flow.md`，技术实现见 `docs/architecture/frontend-architecture.md`。

## 2. 设计目标

| 目标 | 设计要求 |
| --- | --- |
| 清晰 | 用户能够快速理解当前任务、状态和下一步操作 |
| 轻量 | 页面保持留白和低噪声，避免复杂后台系统的沉重感 |
| 稳定 | 所有页面共享相同的应用外壳和组件视觉语言 |
| 温和 | 使用浅灰背景、白色卡片和橙色品牌强调，降低紧张感 |
| 可操作 | 主要操作有清晰的主次、状态和反馈 |
| 可验证 | 状态变化、空状态和错误状态都具有可视化表达 |

## 3. 视觉基调

正式前端延续 HTML 原型的整体方向：

- 浅灰色应用背景。
- 白色内容卡片。
- 橙色作为品牌色和主要行动色。
- 大圆角卡片和轻量阴影。
- 深色标题、灰色辅助文字。
- 通过颜色、状态标签和进度元素表达业务状态。
- 采用类似工作台的左侧导航加右侧内容布局。

整体视觉关键词：

```text
明亮 · 清晰 · 温和 · 轻量 · 有行动引导
```

## 4. 参考图片使用规则

### 4.1 参考图片分类

`prototypes/resources/pics/` 下的图片分为两类：

| 目录 | 用途 | 使用方式 |
| --- | --- | --- |
| `style/` | 整体风格参考 | 参考布局密度、卡片组织、导航和留白 |
| `function template/` | 功能形态参考 | 参考登录、看板、沟通和投递记录等功能表现 |

### 4.2 使用边界

- 参考图片用于提取视觉方向和交互模式，不直接复制其中的品牌、文案或业务结构。
- HTML 原型的实际效果优先于与 Careerpass 业务无关的外部参考图。
- 当前 HTML 原型使用橙色主题，正式前端不得因为参考图中的蓝色、紫色或其它颜色而改变品牌主色。
- 参考图片不得直接作为正式页面背景或核心业务信息的替代品。
- 如果参考图片与流程文档或产品页面规格冲突，以产品文档和 HTML 原型的已确认行为为准。
- 新增图片必须说明来源、用途和是否可以进入正式构建产物。

## 5. 设计令牌

### 5.1 颜色

以下颜色与 HTML 原型当前变量保持一致，正式前端应集中定义为 CSS 变量或等价设计令牌。

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| `--color-bg` | `#f4f5f7` | 应用页面背景 |
| `--color-surface` | `#ffffff` | 卡片、面板和输入区域 |
| `--color-surface-soft` | `#fafafa` | 次级背景和柔和区域 |
| `--color-line` | `#eceef2` | 边框和分割线 |
| `--color-text` | `#17202b` | 标题和主要正文 |
| `--color-input-text` | `#5c6877` | 输入框、文本域和下拉框中的已输入内容 |
| `--color-muted` | `#8c96a3` | 辅助说明和次要信息 |
| `--color-muted-soft` | `#b8bec7` | 弱化提示和占位信息 |
| `--color-brand` | `#ff6a00` | 品牌色、主按钮和当前操作 |
| `--color-brand-dark` | `#e85800` | 主按钮悬停或强调状态 |
| `--color-brand-soft` | `#fff1e7` | 品牌浅色背景 |
| `--color-success` | `#2dbb78` | 成功、完成、Offer |
| `--color-success-soft` | `#e8f8ef` | 成功状态背景 |
| `--color-info` | `#588cf4` | 信息、处理中或辅助状态 |
| `--color-info-soft` | `#edf3ff` | 信息状态背景 |
| `--color-danger` | `#eb6262` | 失败、终止和危险操作 |
| `--color-danger-soft` | `#fff0f0` | 失败状态背景 |

颜色使用规则：

- 同一状态在不同页面使用同一颜色语义。
- 橙色主要用于主操作和品牌强调，不用于大面积正文背景。
- 红色只用于失败、终止或危险操作，不用于普通提示。
- 不能仅依赖颜色区分状态，必须同时提供文字、图标或结构变化。

### 5.2 字体

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", system-ui,
  -apple-system, sans-serif;
```

| 层级 | 建议表现 |
| --- | --- |
| 页面主标题 | 24–34px，较粗，紧凑字距 |
| 区域标题 | 17–25px，较粗 |
| 卡片标题 | 15–18px，中高字重 |
| 正文 | 14px，行高约 1.6–1.7 |
| 辅助说明 | 12–13px，使用辅助文字色 |
| 状态标签 | 12–13px，中高字重 |
| 英文眉标题 | 11–12px，大写、增加字距、使用品牌色 |

中文页面优先保证可读性，不为了追求视觉紧凑而过度缩小正文和表单文字。

### 5.3 圆角和阴影

| 令牌 | 建议值 | 使用场景 |
| --- | --- | --- |
| `--radius-lg` | `24px` | 页面主卡片、Hero 卡片、聊天容器 |
| `--radius-md` | `16px` | 业务面板、进度卡片 |
| `--radius-sm` | `10px` | 输入框、状态标签、小型控件 |
| `--shadow` | `0 10px 28px rgba(28, 37, 48, 0.06)` | 登录卡片和重点浮层 |
| `--shadow-soft` | `0 3px 14px rgba(28, 37, 48, 0.05)` | 普通面板和业务卡片 |

阴影应保持轻量，主要通过背景、边框和留白区分层级，避免强烈悬浮和过度装饰。

### 5.4 间距

建议使用 4px 或 8px 的间距基准：

| 间距 | 用途 |
| --- | --- |
| `4px` | 图标与文字的微小间隔 |
| `8px` | 标签、按钮内部元素和紧凑列表 |
| `12px` | 表单控件、文件卡片内部间距 |
| `16px` | 普通组件间距 |
| `20–24px` | 卡片内边距和区域间距 |
| `28–32px` | 页面主要区块和登录卡片内边距 |

## 6. 页面布局规范

### 6.1 应用外壳

```text
桌面端：左侧导航 + 右侧滚动内容
移动端：顶部或横向导航 + 单列内容
```

| 项目 | 桌面端建议 | 移动端建议 |
| --- | --- | --- |
| 侧边栏 | 约 256px 固定宽度 | 转为顶部或横向菜单 |
| 页面内容 | 最大宽度约 1200–1400px | 100% 宽度，保留 16–20px 边距 |
| 页面内边距 | 28–36px | 16–20px |
| 栅格 | 两列或多列面板 | 单列堆叠 |
| 卡片间距 | 16–24px | 12–16px |
| 页面滚动 | 内容区域独立滚动 | 页面整体滚动 |

### 6.2 侧边导航

- 背景使用白色，右侧使用浅色分割线。
- 品牌区域位于顶部，菜单区域位于中部。
- 当前菜单使用浅橙色背景或品牌色标识。
- 菜单图标和文字保持垂直居中。
- 底部固定当前用户摘要和退出入口。
- 不在侧边栏同时展示过多业务指标。
- 角色切换不通过侧边栏完成，应在登录页或明确的用户入口完成。

### 6.3 页面头部

页面头部应包含：

- 页面标题。
- 简短的页面说明或当前上下文。
- 必要时显示当前状态标签或主要操作。

页面头部不应堆叠长段产品介绍。产品说明应放入欢迎页或引导卡片。

### 6.4 卡片和面板

- 使用白色背景、较大圆角和轻量阴影。
- 卡片内采用明确的标题、状态和内容分区。
- 卡片标题行左侧放标题，右侧放状态或辅助操作。
- 重要操作放在卡片底部或标题行右侧，避免漂浮在不可预测的位置。
- 同一页面的卡片内边距和圆角保持一致。
- 卡片数量较多时，优先使用分组和栅格，不使用过密的边框列表。

## 7. 核心组件规范

### 7.1 按钮

| 类型 | 视觉 | 用途 |
| --- | --- | --- |
| Primary | 橙色实心、白色文字 | 页面主要操作，如上传、创建、启动、发送 |
| Secondary | 白色背景、浅色边框 | 次要操作或取消 |
| Ghost | 透明背景、品牌色文字 | 低强调度的辅助操作 |
| Danger | 浅红背景或红色文字 | 失败、终止或危险操作 |

按钮要求：

- 具备清晰的动词文案，如“上传简历”“创建求职目标”“启动求职 Agent”。
- 操作进行中显示加载状态并禁止重复点击。
- 禁用状态降低对比度，但仍保留可读性。
- 不用颜色单独表达按钮状态，应同时使用文字和交互状态。
- 主要按钮每个页面原则上只保留一个视觉主按钮。

### 7.2 表单

- 标签位于输入框上方，标签文案清晰具体。
- 必填项和可选项明确区分。
- 输入框使用白色背景、浅色边框和中等圆角。
- 输入框、文本域和下拉框中的已输入内容统一使用 `--color-input-text`、`14px`、`400` 字重和 `1.5` 行高；不得继承字段标签的加粗样式，也不得使用纯黑色正文。
- 占位文本使用辅助色和 `400` 字重，与已输入内容保持清晰层级区分。
- 聚焦状态使用品牌色边框或外环。
- 错误提示紧邻对应字段，不能只在页面顶部统一提示。
- 文本域适用于岗位过滤条件等较长内容。
- 数字输入需要限制最小值和合理范围。

### 7.3 文件上传

上传区域使用独立卡片或虚线区域表达，包含：

- 文件类型或用途图标。
- 上传标题。
- 支持格式和使用说明。
- 主上传按钮。
- 上传中、解析中、成功和失败状态。
- 已选择文件的文件卡片。

文件卡片应：

- 使用省略号处理过长文件名。
- 使用统一的信息结构展示上传对象的主信息、版本和上传时间。
- 不展示内部路径、真实存储地址或敏感文件内容。
- Agent 运行中时清晰展示“本轮已绑定”等禁用原因。

#### 7.3.1 `FileInfoCard` 文件信息卡片

简历、其它求职资料和岗位 JD 上传后必须复用同一个 `FileInfoCard`。卡片的容器、图标尺寸、两行文字层级和元数据格式保持一致；首行内容根据上传对象的业务身份变化。

| 区域 | 视觉和内容规范 |
| --- | --- |
| 卡片容器 | 横向 Flex、垂直居中、图文间距 `12px`、内边距 `12px`、边框 `1px solid --color-line`、圆角 `13px`、白色背景 |
| 文件类型图标 | 固定 `38px × 38px`、圆角 `12px`、`--color-brand-soft` 背景、`--color-brand` 文字 |
| 图标文字 | 简历和其它资料使用文件扩展名大写形式，岗位 JD 固定显示“JD”；`10px`、`900` 字重、行高 `1`，必须水平和垂直居中 |
| 主信息 | 第一行；`13px`、`700` 字重、`--color-text`、行高 `1.4`；简历、其它资料和岗位 JD 均展示文件名，超长时省略 |
| 元数据 | 岗位 JD 上传结果第二行展示“上传成功”或“上传失败”；使用 `12px`、`400` 字重、`--color-muted`、行高 `1.5`，并同步显示对应状态标识 |
| 两行间距 | `4px` |
| 删除按钮 | 仅列表资料卡显示；位于右上角 `25px × 25px`，默认弱化，悬停或键盘聚焦时显示；使用“×”和明确 `aria-label` |

使用约束：

- 岗位 JD 上传结果卡片必须且只能展示：左侧固定“JD”图标、上传文件名和“上传成功/上传失败”状态标识。
- 岗位 JD 上传结果卡片不展示岗位名称、公司、地点、薪资、摘要、版本、解析状态或删除按钮；不得在文件卡片下方追加岗位摘要卡片。
- S-11 岗位管理卡片单独承载岗位 JD 删除操作：仅在解析任务为 `succeeded/failed` 且匹配未开始时可用；`queued/running` 或匹配已开始时禁用并显示原因；删除成功后移除卡片，无其他岗位时展示空状态。
- 其它求职资料卡片的删除按钮必须通过 Repository 和 Store Action 删除对应记录，不能由页面直接修改数组。
- 正式简历不提供删除按钮；运行中或已结束时保持当前简历绑定规则。
- 文件类型图标不继承元数据文字的外边距、字号、行高或颜色规则。
- 文件信息内容区设置 `min-width: 0` 和 `flex: 1`，确保长文件名不会挤压图标。
- 单张卡片与上传区域间距为 `16px`；多文件列表内部间距为 `10px`，列表内卡片不得重复增加顶部外边距。

#### 7.3.2 多条上传资料的滚动区域

求职者其它求职资料和 HR 岗位 JD 均使用统一的 `file-list-scroll` 容器承载上传结果列表：

| 项目 | 规范 |
| --- | --- |
| 可见条目 | 默认固定展示最多 4 条文件卡片 |
| 超出行为 | 第 5 条及以后保留在列表中，容器出现可拖动的纵向滚动条；页面主体不因列表增长而整体拉长 |
| 容器高度 | 最大高度 `296px`，按文件卡片高度和 `10px` 列表间距计算 |
| 滚动方向 | 仅允许纵向滚动；横向内容通过文件名或岗位主信息省略处理 |
| 滚动条 | 使用细滚动条，轨道使用 `--color-bg`，滑块使用 `--color-muted`，并保留 `scrollbar-gutter` 防止宽度跳动 |
| 空间关系 | 滚动区域与上传组件间距 `16px`，卡片之间间距 `10px` |

当列表不超过 4 条时仍使用同一容器，但不应出现可滚动内容；当列表超过 4 条时，必须能通过滚动条访问所有已上传资料。

上传控件规范：求职者其它资料和 HR 岗位 JD 的文件输入均启用 `multiple`；用户一次选择的多份文件必须在一次提交中完成处理，并统一进入加载、成功或失败反馈，不得退化为只能选择一份文件。

### 7.4 状态标签

状态标签使用“颜色 + 文案 + 必要时图标”的组合：

| 状态类别 | 建议颜色 | 示例 |
| --- | --- | --- |
| 成功/完成 | 绿色 | 解析成功、已就绪、获得 Offer |
| 处理中 | 蓝色或品牌浅色 | 解析中、Agent 运行中、回复中 |
| 等待 | 灰色 | 尚未开始、等待上传 |
| 失败/终止 | 红色 | 解析失败、流程终止、发送失败 |
| 当前操作 | 橙色 | 可启动、当前选中、主要行动 |

### 7.5 步骤列表与图标组件

求职者流程、HR 标准流程和“当前准备状态”必须复用同一套 `StepListItem` 和 `StepMarker` 组件，不得在页面内分别定义步骤条目或编号样式。

#### 7.5.1 `StepMarker` 步骤图标

基础视觉规范：

| 属性 | 规范值 |
| --- | --- |
| 尺寸 | 固定 `30px × 30px`，不得因文字内容收缩或拉伸 |
| 形状 | `border-radius: 50%` 的正圆形 |
| 对齐 | 使用居中布局，编号或状态符号水平、垂直居中 |
| 字号 | `12px` |
| 字重 | `900` |
| 行高 | `1` |
| 默认内容 | 显示步骤编号；完成状态显示 `✓`；运行中的当前步骤可显示 `…` |

状态颜色规范：

| 状态 | 背景色 | 前景色 | 语义 |
| --- | --- | --- | --- |
| 等待 | `--color-line`（`#eceef2`） | `--color-muted`（`#8c96a3`） | 尚未进入该步骤 |
| 当前 | `--color-brand-soft`（`#fff1e7`） | `--color-brand`（`#ff6a00`） | 当前需要处理或正在进行 |
| 完成 | `--color-success-soft`（`#e8f8ef`） | `--color-success`（`#2dbb78`） | 该步骤已经完成 |

使用约束：

- 左侧流程说明和右侧当前准备状态对同一业务步骤使用相同的状态判定和视觉样式。
- 禁止使用橙色实心背景配白色编号替代上述状态样式。
- 图标颜色必须与编号、对勾或省略号等结构信息同时出现，不能只靠颜色表达状态。
- 页面只能传入步骤编号和等待、当前、完成状态，不得覆盖组件尺寸、圆角、字号、字重或颜色。

#### 7.5.2 `StepListItem` 步骤条目

左侧流程说明和右侧当前准备状态中的每个圆角矩形条目必须使用统一结构：左侧为 `StepMarker`，右侧为标题和说明文字。

| 属性 | 规范值 |
| --- | --- |
| 宽度 | 占满所属列表可用宽度 |
| 最小高度 | `56px` |
| 内边距 | 四周 `13px` |
| 圆角 | `14px` |
| 背景 | `--color-bg`（`#f4f5f7`） |
| 内部布局 | 横向 Flex，`align-items: center` |
| 图标与文字间距 | `12px` |
| 图标位置 | 固定在左侧，并在条目高度内垂直居中 |
| 标题 | `13px`、`700` 字重、`--color-text`、行高 `1.4` |
| 说明文字 | `12px`、`400` 字重、`--color-muted`、行高 `1.5` |
| 标题与说明间距 | `4px` |
| 相邻条目间距 | `12px` |

条目内容区必须设置 `min-width: 0`，长文本允许正常换行；不得通过单独的页面选择器改变标题字重、说明字号、图标位置或条目内边距。

#### 7.5.3 卡片标题栏与步骤列表间距

- 两个步骤卡片使用相同的标题栏高度和列表起始位置。
- 标题栏最小高度为 `28px`，内部元素垂直居中。
- 标题栏与第一条步骤之间固定保留 `18px` 间距。
- 标题、步骤数量提示和状态标签不能通过自身高度改变第一条步骤的纵向位置。
- 左右卡片在同一行展示时，第一条步骤的顶部必须对齐。

### 7.6 进度展示

进度展示至少包含：

- 当前数值和目标数值。
- 当前状态或当前阶段。
- 对应的文字说明。
- 在可能的情况下提供时间或最近更新时间。

求职进度看板可采用以下组合：

- Offer 环形进度。
- 指标卡片。
- 岗位级横向阶段进度条。
- 当前岗位状态标签。

阶段顺序固定为：

```text
已投递 → 初筛中 → 笔试 → 一面 → 二面 → 三面 → HR 面 → 获得 Offer
```

该顺序是完整阶段时间轴的展示顺序，不代表每个岗位必须逐项推进。状态更新允许从当前阶段直接跳转到任一后续阶段，以适配不同公司的招聘流程；不允许回退，终态使用单独的终态约束。

流程终止使用单独的终态标识，不将其伪装成正常阶段进度。

### 7.7 聊天界面

- 左侧展示岗位或候选人会话列表，右侧展示当前会话。
- 当前会话应有明确选中状态。
- HR 与 Agent 消息使用不同的对齐方向或气泡样式。
- 消息内容保持较舒适的行高和最大宽度。
- 发送区域固定在聊天内容底部或视口可见位置。
- Agent 回复中展示明确的处理中状态。
- 没有会话时展示“等待求职者 Agent 发起沟通”等业务化空状态。

### 7.8 空状态、加载和错误

| 状态 | 视觉要求 | 文案要求 |
| --- | --- | --- |
| 空状态 | 居中、留白充足、弱化图形 | 说明当前为什么为空，并提供下一步操作 |
| 加载状态 | 使用轻量骨架、旋转或脉冲效果 | 说明正在进行的动作 |
| 失败状态 | 使用浅红背景或错误图标 | 说明失败结果和可执行的重试方式 |
| 成功状态 | 使用绿色或品牌色反馈 | 说明完成了什么 |
| 禁用状态 | 降低对比度并保留原因说明 | 说明需要先完成什么条件 |

## 8. 页面专项表现

### 8.1 登录页

- 使用独立的居中登录布局，不显示业务侧边栏。
- 登录卡片保持较大圆角和轻量阴影。
- 求职者/HR 身份切换使用清晰的选项卡。
- 品牌、标题、说明、表单和主按钮按垂直顺序排列。
- 登录失败不改变整体布局，错误信息靠近表单区域展示。

### 8.2 求职者任务页

- 目标配置、启动条件和 Agent 状态分成独立面板。
- 任务页可采用左侧配置/启动、右侧当前目标只读查看的双栏组织；右侧不创建第二套编辑入口。
- 启动条件使用步骤清单或状态列表，不使用长段解释。
- Agent 卡片需要突出当前状态和唯一主要操作。
- 启动成功后不展示匹配过程；用户进入求职进度页查看已生成的投递记录、推荐匹配得分和推荐理由。
- 运行中和已结束使用明显但克制的状态色。

S-07 任务页的状态矩阵和双栏验收清单见 [`../development/slice-07-agent-start.md`](../development/slice-07-agent-start.md)。

### 8.3 求职进度看板

- 顶部展示页面标题和当前轮次状态。
- Offer 达成进度作为重点视觉区域。
- 指标卡片采用统一高度、统一内边距和统一数字层级。
- 岗位进度按卡片或列表展示，每个岗位独立呈现进度。
- 投递轮次为 0 时使用完整空状态，不使用空白列表伪装。

### 8.4 HR 工作台

- HR 首页优先展示岗位准备、沟通和进度管理三个步骤。
- 沟通页突出会话选择和消息内容，不让岗位信息压过聊天区域。
- 投递进度页按岗位分组，候选人信息保持摘要化。
- 状态下拉控件只作用于当前投递记录，更新后提供即时反馈。

## 9. 响应式设计

### 9.1 断点策略

建议至少支持以下三种布局状态：

| 状态 | 参考宽度 | 布局 |
| --- | --- | --- |
| 宽桌面 | `≥ 1200px` | 侧边栏 + 多列内容 |
| 窄桌面/平板 | `768px–1199px` | 窄侧边栏或压缩导航 + 两列内容 |
| 移动端 | `< 768px` | 顶部/横向导航 + 单列内容 |

### 9.2 移动端要求

- 侧边导航转为顶部菜单或可展开抽屉。
- 两列面板改为单列堆叠。
- 指标卡片允许横向滚动或改为两列排列。
- 进度时间线允许横向滚动，但不能截断状态文案。
- 聊天界面改为单列，先选择会话再进入消息内容。
- 主按钮在窄屏下可扩展为整行宽度。
- 文件名和长岗位名称必须正确截断或换行。

## 10. 可访问性和交互反馈

- 所有表单控件都有可见标签或等价的可访问名称。
- 图标按钮必须提供 `aria-label` 或可见文字。
- 禁用控件不能只靠半透明表现，还应提供禁用原因。
- 键盘可以访问登录、上传、创建、发送和导航操作。
- 焦点状态清晰可见，不用移除默认焦点而不提供替代样式。
- 状态变化应通过文字或可访问提示让用户感知。
- 颜色对比度满足基本可读要求。
- 进度条提供当前值、最大值和可访问名称。

## 11. 文案规范

### 11.1 文案风格

- 使用简短、直接、面向行动的中文。
- 优先说明用户下一步可以做什么。
- 避免内部技术术语直接暴露给用户。
- Agent、JD、Offer 等产品术语可以保留，但首次出现时应有上下文。
- 错误文案不展示堆栈、内部路径或实现细节。

### 11.2 状态文案统一

| 状态值 | 统一显示文案 |
| --- | --- |
| `processing` | 解析中 |
| `succeeded` | 解析成功 |
| `failed` | 解析失败 |
| `submitted` | 已投递 |
| `screening` | 初筛中 |
| `written_test` | 笔试 |
| `interview_1` | 一面 |
| `interview_2` | 二面 |
| `interview_3` | 三面 |
| `hr_interview` | HR 面 |
| `offer` | 获得 Offer |
| `terminated` | 流程终止 |

状态文案由统一映射提供，页面不得自行改写或混用同义词。

## 12. 设计实现约束

- 正式前端继承原型视觉方向，但不直接复制原型单文件 CSS。
- 颜色、间距、圆角、阴影和字体统一通过设计令牌管理。
- 页面不得使用未经规范定义的品牌主色或状态色。
- 页面不得通过大量内联样式绕过组件样式体系。
- 业务组件不得自行发明状态标签样式。
- 视觉资源应尽量使用 CSS、图标和结构化组件表达，避免依赖大幅截图。
- 设计变更应同步检查登录、资料、任务、进度、岗位和沟通页面的一致性。

## 13. 设计验收清单

### 视觉一致性

- [ ] 页面背景、卡片、文字和边框符合统一色彩令牌。
- [ ] 主要操作统一使用品牌橙色。
- [ ] 页面卡片具有一致的圆角、内边距和阴影层级。
- [ ] 标题、正文、辅助文字层级清晰。
- [ ] 侧边导航和页面内容符合统一工作台布局。

### 交互一致性

- [ ] 所有主要操作有明确按钮文案。
- [ ] 加载、成功、失败、空和禁用状态均有视觉反馈。
- [ ] 上传、解析、Agent、沟通和投递状态表达一致。
- [ ] 失败状态提供可执行的重试或返回路径。
- [ ] 页面不会因长文本、空数据或错误信息破坏布局。

### 响应式和可访问性

- [ ] 桌面端和移动端均可完成核心操作。
- [ ] 侧边栏在窄屏下有合理替代布局。
- [ ] 表单控件有标签和焦点状态。
- [ ] 图标按钮有可访问名称。
- [ ] 状态信息不只依赖颜色表达。
