# 简历 v1→v2 演示排练检查（P1 · 集成在 index 主流程内）

对应页面：`html-reference/index.html`（在原型全功能基础上集成，无独立页面）。  
配置：每岗流式间隔 `DEMO_MATCH_DELAY_MS=2200`，首轮 N=5。

## 排练顺序（求职者主流程）

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 求职者登录 → 求职资料上传，上传简历（v1） | 解析成功，可创建求职目标 |
| 2 | 求职任务：创建求职目标 → 启动求职 Agent | 右下角开始按岗 toast `本轮已匹配 1/5…`、`2/5…` |
| 3 | 求职进度：观察「本轮匹配进度」 | J1–J3 已匹配、J4 匹配中、J5 排队；投递卡标「匹配依据 v1」 |
| 4 | 第 4 岗匹配中时，回到求职资料上传，上传新简历（v2） | 4s 内 toast「检测到简历已更新为 v2，正在调整匹配任务…」 |
| 5 | 求职进度：观察调整结果 | 未完成岗（J4/J5）→「已取消」→ 自动 M2 →「已匹配 v2」；J1–J3 保持 v1 |
| 6 | HR 登录 → 求职沟通，打开 J1 会话 | 头部显示「会话简历 v1」，并提示本会话锁定开启版本（P1） |
| 7 | 运行中重复触发（或 M2 进行时）同一范围匹配 | 幂等：toast「匹配正在进行中，已避免重复触发」，无重复 run |

## 验收要点

- AC1 按岗 toast；AC2 换 v2 后快速出现调整 toast；AC3 done 岗结果与会话保留；
  AC4 M2 仅含未完成岗且 resume_version=2；AC5 会话绑定 v1 不随 active 漂移；AC6 幂等；AC7 产品内投递 = HR 可见会话。
- 禁止：v2 不覆盖已开会话材料；不对已完成岗全量重匹配。

目标总时长 ≤ 3 分钟（含 15s 口播）。

## 集成说明

本演示不新增独立页面，全部能力融入 `index.html` 既有流程：
- 启动 Agent → `runRoundMatching` 按岗流式匹配并逐岗推送 toast + 创建产品内投递会话。
- 求职资料上传页在 Agent 运行中允许替换简历 → `orchestrateOnResumeChange` 冻结已完成岗、取消未完成岗、基于新版本发起 M2。
- 投递会话绑定 `resumeVersionAtOpen`，沟通页按 P1 展示会话锁定版本。
