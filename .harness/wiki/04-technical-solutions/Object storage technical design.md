# 对象存储技术方案

## 1. 定位与边界

本方案是文件对象存储的唯一技术权威来源，适用于简历、候选人附加资料及岗位 JD 的原始文件。MVP 使用本地对象存储适配器，存储根目录、临时目录和正式对象目录均由运行配置提供，且不得由 Web 静态服务暴露。

`stored_file_objects` 是仅供对象存储适配器和 Repository 使用的内部对象目录，不是面向用户的通用文件中心。表结构、外键和枚举以 [数据模型](../03-contracts/Data%20model.md) 为准；文件类型、大小和用户可见边界以 [MVP 范围与开发边界](../01-governance/MVP%20scope%20and%20development%20boundaries.md) 为准。

## 2. 文件校验与业务边界

| 业务资源 | 允许格式 | 是否解析 |
| --- | --- | --- |
| `resumes` | PDF | 是，具体链路以[简历解析技术方案](Resume%20parsing%20technical%20design.md)为准 |
| `candidate_documents` | PDF、Markdown、JPG/JPEG | 否，仅作系统内消息原始附件 |
| `job_descriptions` | 由岗位 JD 接口另行定义 | 是 |

- 所有上传入口的单文件上限为 10 MB（10,000,000 bytes）。
- 服务端同时校验扩展名、声明 MIME、文件特征和业务资源类型；业务逻辑只信任服务端检测结果。
- 文件格式只决定上传校验，不决定是否进入解析。候选人附加资料的正文在 MVP 中不自动进入 Agent/LLM 输入；Agent 仅可经业务授权获取最小附件元数据。

## 3. 对象目录与去重

`stored_file_objects` 保存随机且不透明的 `storage_key`、服务端计算的 SHA-256、检测 MIME、字节数和内部状态。`storage_key` 与摘要均唯一；业务资源只保存 `stored_file_object_id` 外键。

底层对象按 SHA-256 去重，但业务资源不去重：相同内容可由多个简历或候选资料引用，每次上传仍创建独立的资源、归属、审计和解析生命周期。不得使用文件名、候选人 ID、客户端路径或模型输出构造对象键或去重键。

## 4. 上传与建档流程

1. 上传流仅写入受限临时目录，并在流式写入时累计字节数；超过上限立即中止并删除临时文件。
2. 上传完成后校验类型，计算 SHA-256 和检测 MIME。校验失败时不创建对象目录记录、业务资源或解析任务。
3. Repository 以摘要取得事务级锁并查询对象目录：已有 `ready` 对象时复用；否则创建 `writing` 对象记录并生成随机 `storage_key`。
4. 新对象必须在同一文件系统内原子移动到正式目录。文件移动成功后，在数据库事务中将对象标记为 `ready` 并创建业务资源；简历和岗位 JD 在其资源事务中同时创建可靠入队记录。
5. 同摘要并发上传在摘要锁下串行处理。重复投递只复用已就绪对象，不能合并业务资源。

文件系统和数据库无法构成单一原子事务时，以对象状态和无引用清理兜底：`writing` 对象不得被业务资源引用；在移动或建档中断后留下的对象不可被读取，等待清理。

## 5. 受控读取

- 不提供原始文件下载、预览、公开链接、预签名 URL、静态路径或 `storage_key`。
- Service、Agent、Workflow 不得直接读本地文件系统。调用方只能提供业务资源 ID 与受限用途，由 Repository 校验归属、资源状态、对象状态和用途后调用存储适配器打开流。
- 简历解析任务仅能读取自身资源关联的 `ready` 对象。岗位 JD 启动导入不使用候选人对象存储；候选人附加资料不向解析器、Agent 或 LLM 提供正文。
- 对象缺失、读取失败或状态非 `ready` 时，解析任务按 `storage_unavailable` 处理；接口和日志不得暴露路径、摘要或文件正文。

## 6. 清理与恢复

| 对象情形 | 处理 |
| --- | --- |
| 上传中断或校验失败的临时文件 | 立即删除 |
| `writing` 超过 1 小时且无资源引用 | 清理任务删除 |
| `ready` 超过 1 小时且无资源引用 | 清理任务删除；仅覆盖建档/入队中断遗留对象 |
| 任意仍被资源引用的对象 | MVP 不删除；当前不提供用户删除接口 |

清理任务每小时执行一次，使用行锁领取对象；删除前必须在事务中复核不存在任何 `resumes` 或 `candidate_documents` 引用，再标记为 `deleting`、删除物理文件并删除目录记录。任务必须幂等。文件删除失败时保留或恢复为可重试状态；不得删除共享对象。审计只记录关联 ID、状态和脱敏原因，不记录路径、文件名或正文。

## 7. 验收

- 同内容并发上传只产生一个内部对象，且产生独立业务资源。
- 上传中断、类型不合法、大小超限、文件移动失败和建档失败均不留下可读取的对象。
- 非所有者、Agent 和 Workflow 无法绕过 Repository 读取原始文件。
- 清理任务不会删除仍有任意资源引用的对象，并能清理超过宽限期的无引用对象。
