# 影响分析

## 受影响模块与边界

| 模块 | 影响 | 所有权/权限影响 | 备注 |
| --- | --- | --- | --- |
| 候选人资料准备与文档解析 | 明确对象存储、异步解析、画像为条件能力，并要求首用时与业务闭环一起验证 | 简历和画像始终按候选人归属校验 | 不新增上传或解析接口 |
| 岗位 JD 管理与岗位匹配 | 定义 R0-R4 检索演进与启用条件 | 匹配输入必须来自当前候选人有权使用的资料、目标和岗位 | 向量召回不自动成为 MVP 阻塞项 |
| 投递、进度与 AI 沟通 | 明确 Agent 计划不能绕过状态机、授权或系统内副作用边界 | 投递、会话和进度继续使用其既有归属锚点 | 不开放真实外部动作 |
| Agent 与工作流 | 定义结构化计划、注册工作流、调度状态、幂等和审计规则 | 调度前复核资源归属、状态与授权 | 不实现可视化编排平台 |
| 开发流程与变更模板 | 要求任务关联业务结果和技术能力 | 无运行时权限变化 | 后续变更包必须标记首次交付或复用 |

## 契约与数据影响

- API：无运行时 API 变更；未来 Agent 或任务接口须遵守新增计划与调度契约。
- 数据库与 Alembic：无；工作流运行记录和审计事件仅在首个实际实现流程时另行设计与迁移。
- Redis/Celery：无配置或键变更；未来异步流程须遵守状态、幂等和有限重试规则。
- LLM、Prompt、追踪脱敏：计划与模型输出必须结构化校验；审计和追踪只记录脱敏最小元数据。

## 风险与缓解

| 风险 | 等级 | 缓解措施 |
| --- | --- | --- |
| 将治理文档误解为立即建设通用平台 | medium | 明确首次实际使用才交付最小能力，并将可视化与动态编排列为延期 |
| RAG 被错误作为所有模块前置条件 | high | R0-R4 分层并以质量评估和匹配模块实际需求为启用条件 |
| Agent 计划绕过业务授权或状态机 | high | 要求注册工作流、Pydantic 输入、调度前复核及审计事件 |
