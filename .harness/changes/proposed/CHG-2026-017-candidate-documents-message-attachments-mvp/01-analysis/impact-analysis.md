# 影响分析

## 受影响模块与边界

| 模块 | 影响 | 所有权/权限影响 | 备注 |
| --- | --- | --- | --- |
| 候选人资料准备 | 附加资料纳入 MVP 上传、查询与受控存储 | 必须按 `candidate_id` 校验 | 不参与简历、画像或下游业务前置条件 |
| 文档解析 | 不处理候选人附加资料 | 不适用 | 仅简历和岗位 JD 进入解析 |
| AI 求职沟通 | 消息可引用候选人明确选择的原始资料附件 | 会话候选人与资料候选人必须一致 | 仅系统内模拟发送；资料正文不进入 Agent/LLM 上下文 |
| 数据模型 | 业务资源外键引用内部文件对象，消息附件再引用候选人资料 | 通过归属链避免跨候选人引用 | 内容摘要去重不合并业务资源；不复制文件或资料正文 |

## 契约与数据影响

- API：候选人资料接口进入 MVP；发送消息新增可选资料引用。
- 数据库与 Alembic：数据模型已定义内部文件对象目录、资料表和附件引用表；实际实现需新增 Alembic revision。
- Redis/Celery：候选人资料不创建异步解析任务。
- LLM、Prompt、追踪脱敏：候选人资料不得进入 Agent/LLM 上下文；不得记录文件正文、文件地址或凭证。

## 风险与缓解

| 风险 | 等级 | 缓解措施 |
| --- | --- | --- |
| 跨候选人引用附件 | high | 在 Repository 中原子校验会话归属链和资料归属链 |
| 原始资料被 Agent 当作事实使用 | high | 资料仅可作系统内消息附件，禁止读取资料正文或作为 Agent/LLM 上下文 |
| 附件复制导致隐私和数据不一致 | medium | `message_attachments` 只保存资料引用，不保存文件或资料正文 |
| 去重对象被过早清理 | high | 清理前以事务锁复核所有资源引用；仅清理超过 1 小时宽限期的无引用对象 |
