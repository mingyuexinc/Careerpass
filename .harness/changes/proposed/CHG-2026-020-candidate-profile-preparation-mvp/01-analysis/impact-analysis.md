# 影响分析（当前版本）

> 本节为 2026-08-01 开发者确认后的阶段 1 影响分析，后文“历史版本”内容全部废止，不得作为当前需求、设计、任务或验收依据。

## 1. 模块边界

候选人资料准备模块只负责已认证候选人的资料上传闭环：输入校验、受控对象存储、幂等处理、候选人归属校验、资料记录创建以及本人资料元数据查询。

本模块不负责解析请求、解析任务、解析状态、Dispatcher、Celery Worker、MinerU、Qwen、候选人画像、匹配、投递或沟通准入。

## 2. 影响范围

| 依赖/模块 | 关系 | 本模块使用范围 |
| --- | --- | --- |
| 认证与当前身份 | 上游公共能力 | 取得 `CurrentIdentity(user_id, candidate_id)`，执行候选人归属校验 |
| Repository 与 PostgreSQL | 基础设施复用 | 保存对象元数据、资料记录、幂等关系和归属关系；Service 不直接访问 ORM/SQL |
| 本地对象存储抽象 | 本模块直接技术依赖 | 受控写入、不透明对象键、摘要去重、失败清理和无引用对象清理 |
| 文档解析模块 | 后续业务模块 | 不调用、不读取内部实现；其后续处理不构成本模块上传验收条件 |

## 3. 数据与事务影响

- 涉及 `stored_file_objects`、`resumes`、`candidate_documents` 及其引用、幂等和候选人归属关系。
- 数据库事务只保证本模块自身的对象元数据、资料记录、幂等关系和归属关系一致；不创建或持久化解析任务。
- 文件字节由对象存储适配器管理；数据库事务失败时清理本次未被引用的对象，避免悬挂文件。

## 4. API 与安全影响

- 受影响入口为正式简历和候选人附加资料的上传、列表及本人元数据查询 API，统一返回 `{code, msg, data}`。
- 所有读取和修改均通过当前候选人归属校验；跨候选人访问返回安全空结果或 `404`。
- API、日志和追踪不得暴露原文、联系方式、对象键、物理路径、凭证或异常堆栈。

## 5. 非目标与验收边界

- 本模块验收止于资料已受控写入并形成候选人自有资料记录。
- 下游模块如何发现或处理已上传资料，由独立跨模块机制或文档解析模块另行裁决；不作为本模块实现依赖或验收前置。
- 本模块不需要预验证 MinerU、Qwen、Celery、Dispatcher 或其他解析技术能力。

## 历史版本（废止）

- 认证后的候选人资源新增归属校验入口；所有查询均以可信 `candidate_id` 过滤。
- 本地对象存储仅接受服务端生成的不透明键，API 不返回路径、文件正文或解析原始错误。
- MinerU/Qwen 凭证仅作为解析 Worker 条件依赖；凭证真实可用性须由外部集成全链路证明。
- 关联 CHG-017、CHG-018 与 CHG-019 的附件、画像和上传幂等契约。
- 子任务 8 将原先位于候选人资料准备模块的画像查询、终态持久化及解析任务创建迁移至文档解析模块；资料模块只通过 `ResumeParseRequestV1` 提交受控请求，不依赖文档解析的 ORM、Repository、任务状态或 Worker 实现。
- 保持 `GET /api/v1/resumes/{resume_id}/profile` 的外部 URL，处理器和 Service 归属迁移为文档解析模块，避免破坏既有调用方。
