# 影响分析

## 受影响模块与边界

| 模块 | 影响 | 所有权/权限影响 | 备注 |
| --- | --- | --- | --- |
| 认证与会话 | 明确身份解析与错误语义 | User/Candidate 关联必须复核 | MVP 与 Deferred 分界须一致 |
| 候选人资料准备 | 定义准备度派生状态 | 所有资料按候选人归属读取 | 不持久化派生状态 |
| 文档解析 | 定义解析状态、重试和幂等边界 | 资源归属与敏感数据保护 | 不写入半成品 |
| 后续业务模块 | 建立状态机章节骨架 | 后续实现前必须补充规则 | 本次不实现业务行为 |

## 契约与数据影响

- API：无运行时变更；为后续 API 前置条件与错误语义提供依据。
- 数据库与 Alembic：无；规则不得替代正式数据模型审查。
- Redis/Celery：文档解析相关规则规定后续任务需可追踪、重试与幂等。
- LLM、Prompt、追踪脱敏：规定结构化校验与最小必要信息原则。

## 风险与缓解

| 风险 | 等级 | 缓解措施 |
| --- | --- | --- |
| 规则与 MVP 实现范围冲突 | high | 以 MVP 范围文档为裁决基准，显式标记 Deferred。 |
| 后续绕过资源归属 | high | 将候选人归属校验写为不可降级前置条件。 |
| 异步任务产生重复或半成品数据 | high | 在规则中定义幂等、状态追踪与失败边界。 |
