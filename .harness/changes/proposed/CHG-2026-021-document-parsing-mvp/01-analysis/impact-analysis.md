# 影响分析

## 范围裁决

文档解析是独立业务模块。它消费已授权的版本化请求，输出已校验的结构化事实或有限安全失败分类；不发起匹配、投递或 AI 沟通等下游动作。

简历解析与候选人画像属于同一结构化处理链路。手工录入岗位 JD 的解析同样属于本模块，但其请求契约、持久化结果和运行时编排尚未开发。

## 依赖与数据流

`候选人资料准备 → ResumeParseRequestV1 → Dispatcher → resume Worker → MinerU → Qwen → Pydantic/业务校验 → candidate_profiles + resume/task 终态`

`岗位管理 → JobDescriptionParseRequest（待定义）→ Dispatcher → JD Worker（待实现）→ 受控提取/结构化校验 → JD 结构化结果 + JD/task 终态`

两个上游模块只能依赖各自请求和结果契约，不能调用文档解析的内部 Service、Repository、存储或任务实现。

## 风险与门禁

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| Redis/Worker/数据库未做真实联通验证 | 简历任务可能无法从发布走到租约领取 | 子任务 2 必须在隔离真实依赖中完成；当前为 blocked |
| 外部提供方行为与单适配器预验证不同 | 可能无法写入原子画像终态 | 子任务 3 采用受控脱敏 PDF 和真实 Worker 拓扑验证 |
| 重试或旧租约写入 | 重复画像或错误终态 | 子任务 4 覆盖租约、失败映射和原子性 |
| JD 分支缺失 | MVP 的岗位解析链路无法交付 | 子任务 5-7 独立实现，不与简历验收混用 |

## 已完成能力的适用范围

已完成项仅证明简历分支的代码级能力和单适配器外部预验证；不证明真实全链路，也不覆盖 JD 解析。
