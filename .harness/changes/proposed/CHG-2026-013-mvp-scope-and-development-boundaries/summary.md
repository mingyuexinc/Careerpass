# MVP 范围与开发边界

## 变更概述

新增 MVP 范围与开发边界 Wiki 文档，明确 Agent 核心求职闭环、模块最小交付、延期能力与不可降级约束；对认证与用户初始化、候选人资料准备模块补充模块级范围裁决，使用交付目标、内部裁决、输入输出边界及验收口径承载表格无法表达的关键细节。解析边界按业务资源类型划分：仅简历与岗位 JD 进入异步解析；候选人附加资料是候选人显式选择的系统内沟通原始附件，不进入解析、画像、匹配或 Agent/LLM 上下文。画像裁决为成功简历解析的确定性派生结果；并将该文档加入 `AGENTS.md` 文件索引，作为每次需求开发前的范围裁决基准。

## 影响模块

- 认证与用户初始化
- 候选人资料准备、文档解析与本地对象存储
- 求职目标、岗位管理与岗位匹配
- 投递进度与 AI 求职沟通

## 数据库变更

本提案更新逻辑数据模型：新增仅供存储适配器和 Repository 使用的内部文件对象目录，以内容摘要唯一约束管理去重、对象状态和清理；`resumes` 与 `candidate_documents` 均以外键引用内部对象。候选人资料移除 `parse_data`、`parse_status` 及其异步任务关联，作为原始消息附件资源；消息附件去除“候选资料解析成功”的前置条件。评审用数据迁移与回滚脚本由关联的 CHG-017 提供；进入编码实现时仍必须通过工程 Alembic revision 执行，不得直接运行评审 SQL。

## API 变更

候选人资料上传与列表接口不再返回 `parse_status` 或 `failure_code`；发送消息时的 `candidate_document_ids` 不再要求解析成功，改为校验资料对象存在、归属一致且由候选人本次明确选择。接口不得返回文件地址、文件正文或内部存储细节。

## Redis 变更

无。

## 关键约束

- MVP 仅验证系统内的 Agent 核心求职闭环，不执行真实外部投递或消息发送。
- 延期能力不得成为 MVP 开发依赖或验收阻塞项。
- 用户归属校验、敏感信息保护、异步幂等和 LLM 输出校验属于不可降级约束。
- 文件格式只用于上传校验；是否解析由资源业务类型决定，不能由 PDF、Markdown 或 JPG/JPEG 等格式推导。
- `candidate_documents` 仅作为系统内消息原始附件，不能作为 Agent/LLM 上下文；资料内容分析须在后续独立评审并取得明确授权。
