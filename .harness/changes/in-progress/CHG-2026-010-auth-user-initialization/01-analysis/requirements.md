# 认证与用户初始化需求分析

> 标记说明：
>
> - 【开发者已确认】项根据既有 MVP 范围、接口契约、实现与验证记录起草，并于 2026-07-31 由项目开发者确认。
> - 【共同补全】项由既有变更包、测试和运行记录归纳，仍须由开发者复核。
>
> 本文档仅补充受控 Demo 的最小认证闭环，不将未来生产化账号体系纳入本期范围。

## 1. 背景与业务价值【开发者已确认】

- 要解决的用户问题：受邀测试的个人求职者需要以稳定、可验证的身份进入系统；后续简历、画像、求职目标、匹配、投递和沟通资源才能按候选人归属受控访问。
- Demo 成功标准（可重复演示的输入、动作和可观察结果）：使用隔离测试账号完成注册或登录，获得短期 Access Token；携带 Token 调用 `/api/v1/auth/me` 返回与该账号一对一关联的 User 和 Candidate 最小身份信息；重复用户名注册返回 `409`，错误凭据或无效 Token 返回不泄漏账户状态的 `401`。
- 不实现本模块对核心闭环的影响：后续模块无法得到可信 `CurrentIdentity`，无法执行候选人级资源归属校验，核心求职闭环的安全边界不成立。
- 本模块优先级与原因：最高优先级的公共身份域基线；它是所有候选人资源操作的前置能力，而非可选的账户体验增强。

## 2. 用户、角色与授权【开发者已确认】

- 使用者/触发者：受邀测试的个人求职者；注册和登录均由未认证访问者主动发起。
- 资源所有者：`users` 是账户主体；每个 `users` 记录唯一关联一个 `candidates` 记录，候选人是后续求职资源的归属锚点。
- 各角色的读取、创建、更新、删除、执行权限：
  - 未认证访问者：可创建自己的账号、提交登录凭据；不可指定或读取任意 `user_id`、`candidate_id`。
  - 已认证候选人：可读取自己的 `/auth/me` 最小身份；本模块不提供用户资料更新、删除、角色管理、会话管理或管理员操作。
  - 管理员、运营人员、第三方应用：本期不提供角色、接口或越权访问能力。
- 资源归属或访问授权链：`Authorization: Bearer <access_token>` → JWT 签名、签发方、受众和过期时间校验 → `user_id` → Repository 复核 User 存在 → Repository 取得唯一 Candidate → 后续资源以 `candidate_id` 校验归属。
- 越权访问、未认证访问的预期行为：缺失、无效或过期 Token，以及 User/Candidate 关联异常，统一返回 `401`；后续业务资源不得仅凭资源 ID 访问。认证公开接口不返回“用户不存在”与“密码错误”的可区分信息。

## 3. MVP 范围裁决【开发者已确认】

- 本期必须交付：用户名密码注册；用户名密码登录；`GET /api/v1/auth/me`；短期 Access Token 的签发/校验；密码安全哈希存储；注册时原子创建 User 与 Candidate；统一当前身份解析。
- 本期明确不做：Refresh Token、刷新/登出接口、设备管理、长期会话、Token 轮换、密码找回、邮箱/手机号验证、第三方登录、管理员账号管理与多租户运营。
- 延期能力：服务端会话持久化、账号禁用/风控、公开注册增长、防御体系运营化和跨设备安全管理；触发条件见 MVP 范围文档的延期项裁决。
- 与核心用户路径的关系：处于“注册 / 登录 → 上传简历 → 解析 → 画像 → 匹配 → 投递 → 沟通”路径的起点，为后续模块提供可信候选人上下文。
- 上游前置模块与下游消费者：依赖平台基础设施（CHG-2026-009）的 FastAPI、配置、PostgreSQL、Alembic 与统一响应；下游消费者为所有候选人资源 API、Service、Repository 与工作流。
- 最小实现（删减后仍可完成演示的边界）：只保留单一用户名密码身份方式、短期 Access Token 及 `/auth/me`，并在数据库中原子初始化 User/Candidate；不增加会话管理或身份运营能力。
- 不纳入理由（为未来生产、运营、规模或通用性而提出的能力）：上述延期项不增加受控 Demo 对“候选人可安全进入核心闭环”的证明能力，且会引入额外会话生命周期、审计和运营决策。

## 4. 最小行为与输入输出【开发者已确认】

| 项目 | 说明 |
| --- | --- |
| 触发者与入口 | 未认证访问者通过 `POST /api/v1/auth/register` 或 `POST /api/v1/auth/login` 触发；已认证候选人通过 `GET /api/v1/auth/me` 读取身份。 |
| 处理对象与来源 | 注册/登录请求中的用户名、密码与可选姓名；身份事实以 `users`、`candidates` 及服务端 JWT 配置为准。 |
| 输入约束 | 用户名长度 3–64 且仅允许字母、数字、`_`、`.`、`-`；密码非空且最长 128；姓名可选且最长 64。 |
| 最小处理 | 注册时 Pydantic 校验、scrypt 哈希、单事务创建 User/Candidate、签发 Token；登录时校验凭据和 Candidate 关联后签发 Token；`/me` 重新解析并复核身份。 |
| 输出与消费者 | 统一 `{code, msg, data}` 响应；注册/登录仅返回必要的 Access Token、有效期及最小身份；`/me` 返回本人最小身份和 `profile_status: incomplete`；下游仅消费可信 `CurrentIdentity`。 |
| 保留方式 | User/Candidate 作为账户与资源归属基础数据持久化；本期不保留 Refresh Token 或服务端会话。 |
| 明确不做 | 不提供 HTTP 刷新、登出、密码重置、资料编辑、角色授权管理、外部身份提供方接入或对外消息副作用。 |

## 6. 安全、隐私与模块边界【开发者已确认】

- 敏感数据、凭证、路径、原文和模型输出的处理边界：密码仅在请求处理期间用于哈希或校验；密码哈希、JWT、完整连接串和 JWT 密钥均不得出现在日志、追踪、Prompt、变更记录或非必要响应；本模块不处理简历原文、文件路径或模型输出。
- 日志、追踪、Prompt 和 API 响应的最小化要求：日志只记录方法、路径、状态、耗时和关联 ID 等最小诊断信息；认证失败不泄漏账号存在性、候选人关联状态或底层异常；Access Token 只在注册/登录成功的必要响应中返回。
- 不得跨越的模块、Service、Repository、事务或数据访问边界：API 仅负责契约、依赖注入和响应；Service 不访问 ORM Session 或编写 SQL；Repository 独占 User/Candidate 查询与原子创建；JWT 解析集中在统一认证依赖；后续业务模块不得解析 Token 或信任客户端传入的当前身份 ID。
- 审计、授权或合规要求：注册的 User/Candidate 必须同事务提交或回滚；受保护请求必须重新复核数据库关联；本期不引入服务端会话、设备或认证风控运营能力。

## 7. 验收与演示【共同补全】

- 注册合规账号后，响应为 `{code: 200, msg: "success", data: ...}`，且数据库中存在唯一关联的 User/Candidate。
- 已注册账号以正确密码登录后获得短期 Access Token。
- 使用该 Token 调用 `/api/v1/auth/me`，得到与注册账号一致的最小身份。

## 8. 影响分析与发布策略【共同补全】

- 受影响模块、接口、数据表、迁移和前端：影响认证 API、统一身份依赖、后续候选人资源授权、`users`/`candidates` 表、唯一约束与更新时间触发器；当前无前端页面交付范围。
- 兼容性、数据迁移与回滚方案：新增迁移通过 Alembic 执行；重复升级需安全。若尚未承载需保留数据，可按 `04-data/rollback.sql` 或对应 Alembic downgrade 依赖反序回滚；一旦存在需保留账户数据，只回滚应用并制定数据迁移方案。
- 发布、就绪检查和观测要求：本期受控 Demo 使用隔离环境；发布前确认服务可连接 PostgreSQL、JWT 密钥不使用示例值，并验证注册、登录与 `/auth/me` 冒烟；禁止记录凭据与 Token。
- 演示证据与非生产化声明（如何重复演示；明确未覆盖的规模、运营和可用性能力）：使用隔离 PostgreSQL 环境完成注册、登录与身份读取；不宣称已覆盖公开注册规模、账号运营、灾备、高可用、会话轮换、认证风控或外部身份系统。
- 风险、假设与缓解措施：账户名冲突由数据库唯一约束和事务处理；凭据泄漏由 scrypt、最小响应和脱敏日志约束；身份漂移由每次受保护请求 Repository 复核。
