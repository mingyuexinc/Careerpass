# 关联资源归属锚点契约修订

## 变更概述

删除匹配批次、匹配结果、投递记录和沟通会话中的冗余候选人关联，以求职目标或投递记录作为唯一归属锚点，避免同一记录写入互相矛盾的候选人 ID。

## 影响模块

- 岗位匹配
- 投递管理
- AI 求职沟通
- Repository 数据访问

## 数据库变更

- 匹配批次表删除 `candidate_id` 及其外键、索引。
- 投递记录表删除 `candidate_id` 及其外键、索引。
- 沟通会话表删除已失效的 `fk_conversation_candidate` 外键。
- 归属关系通过 `job_goal_id` 或 `application_id` 的关联链获取。

## API变更

无；接口不得再接受或返回已删除的冗余候选人字段。

## Redis变更

无。

## 关键约束

Repository 必须在同一事务中验证简历、画像和匹配结果与归属锚点的候选人一致，所有资源访问均须沿归属链校验当前候选人。

## 回滚方案

恢复冗余字段前必须先完成历史数据回填和一致性校验；本次仅修订文档契约，不执行数据库迁移。

## 关联与实施状态

- 关联需求/变更包：无。
- 当前状态：已确认，待实现。

## 验收标准

- 资源查询与修改均沿求职目标或投递归属链校验当前候选人。
- 表和接口不再读写已删除的冗余候选人关联字段。
