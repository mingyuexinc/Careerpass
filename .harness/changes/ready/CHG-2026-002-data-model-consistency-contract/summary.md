# 数据模型一致性契约修订

## 变更概述

修复索引命名、异步解析状态、会话最后消息时间维护，以及投递、消息和附件字段在业务模型与数据模型之间的不一致。

## 影响模块

- 文档处理
- 岗位管理与岗位匹配
- 投递管理
- AI 求职沟通
- 数据库基础设施

## 数据库变更

- 所有二级索引改为表前缀命名，确保 PostgreSQL Schema 内名称唯一。
- 简历、求职者资料、岗位 JD 和消息附件的 `parse_status` 统一为 `NOT NULL DEFAULT processing`。
- 会话 `last_message_at` 由消息插入触发器 `set_conversation_last_message_at()` 维护。

## API变更

应用、消息和附件 Schema 使用 `match_result_id`、`status`、`role`、`file_url` 作为统一字段名。

## Redis变更

无。

## 关键约束

- 索引名称采用 `idx_<table>_<column>` 格式。
- 解析任务创建后必须从 `processing` 状态开始，随后仅迁移至 `succeeded` 或 `failed`。
- 会话最后消息时间只由消息写入触发器更新。

## 回滚方案

实际数据库迁移时，按反向顺序恢复索引名、字段约束和触发器；本次仅修订文档契约。

## 关联与实施状态

## 验收标准

- 数据模型、业务模型和接口 Schema 的字段名与状态契约一致。
- 索引、解析状态和会话最后消息时间维护通过迁移与自动化测试验证。
