# 切片设计

## 工作流程

1. 阅读根项目和目标子工程的 `AGENTS.md`。
2. 阅读 `docs/business/business-baseline.md` 和 `docs/business/business-fact-extraction.md`，先确认候选 Slice 依赖的业务事实编号及其状态。
3. 阅读前端流程、后端交付范围、能力映射、差距分析、切片计划以及相关当前事实源。
4. 确认切片只有一个触发条件、一个主要可观察结果，明确范围和不包含范围，并且前置切片已经满足。
5. 根据项目模板创建或更新对应的 `slice-spec.md` 和 `technical-design.md`。
6. 在 `slice-spec.md` 中引用业务事实编号，不复制或改写已确认的跨前后端业务规则。
7. 明确本 Slice 的所有权、授权、接口与任务契约、状态迁移、数据变化、依赖、失败行为和验收条件。
8. 在生产者切片文档中记录跨切片交接契约；消费者只引用相同的契约编号和版本，不建立全局契约注册表。
9. 使用首次接入外部依赖的真实证据完成就绪检查，并确认受影响的全局文档已经同步。
10. 将影响当前 Slice 的 `pending` 事实或未解决的关键决策标记为阻塞；不得开始实现，也不得把关键决策隐藏在任务清单中。

## 边界

- 将代码和迁移视为实现证据，但不能据此自动批准当前行为。
- 不得从归档材料中复制尚未实现的实体、接口、状态或未来设计。
- 每项事实只保留一个来源：跨前后端业务事实写入 `docs/business/business-baseline.md`，切片专属业务细节写入 `slice-spec.md`，技术细节写入 `technical-design.md`，稳定的后端技术事实写入对应的后端文档。
- `pending` 业务事实不能由 Coding Agent 通过实现细节自行裁决；只阻塞受影响的 Slice。
- 不得暴露凭证、敏感原文、内部存储路径或模型原始响应。
