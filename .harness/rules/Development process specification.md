## 单个功能模块开发任务模板

本模板适用于正式功能模块中的每个开发任务，并作为阶段 3“任务拆分”的最小描述单元。每项任务预计纯开发时间不得超过 4 小时；跨任务依赖必须在任务开始前明确。

### 使用规则

- **数据校验是通用硬门禁**：开始开发前，必须确认当前任务所需的输入数据存在、格式正确、字段完整、业务状态可用且归属关系合法。任一必需数据不满足时，任务状态为 `blocked`，应先提示补齐数据，不进入实现。
- 数据前置条件应以任务自身为准。例如“生成候选人画像”要求可用的已解析简历；“上传简历”则以用户上传的文件为输入，不要求数据库中预先存在简历。
- **必需依赖是开发前门禁**：认证、Repository、数据库、接口契约等通用依赖，以及本任务声明为必需的 LLM、对象存储、向量库、异步队列等条件依赖，均须完成可用性检查。外部工具需确认配置存在、权限和配额有效，并在有限超时内完成不含敏感信息的连通性验证。
- 异步任务、LLM、Embedding、向量库、对象存储和第三方平台均为条件依赖；仅在任务实际使用时填写，不得将其作为所有任务的固定前置条件。
- 测试替身仅用于单元测试和故障分支覆盖，不得替代正式功能任务的必需依赖检查。
- 涉及用户资源的任务，必须同时通过身份认证和资源归属校验；涉及状态变更或外部副作用的任务，必须定义合法迁移、明确授权与审计记录。

### 任务描述模板

```markdown
#### T{编号}：{任务名称}

**开发目标**

- {要解决的业务问题、范围和明确非目标}

**输入数据与数据校验**

| 输入 | 来源 | 必填 | 校验规则 | 不满足时的处理 |
| --- | --- | --- | --- | --- |
| {例如 resume_id} | {请求参数 / Repository / 文件} | 是 | {存在性、格式、完整性、状态、归属} | {blocked / 返回安全错误} |

**依赖检查**

| 依赖 | 类型 | 必需 | 检查标准 | 未就绪处理 |
| --- | --- | --- | --- | --- |
| {认证与当前用户} | 通用 | 是 | {可识别当前 user_id} | blocked |
| {Repository / 数据库} | 通用 | 是 | {接口、Schema、迁移可用} | blocked |
| {LLM / 队列等} | 条件 | {是/否} | {配置、权限、超时内连通性} | {blocked / 按已定义降级} |

**处理规则与边界**

- {身份认证与资源归属校验链路}
- {业务规则、状态前置条件和合法状态迁移}
- {Pydantic 校验、LLM 输出校验、幂等键或授权要求（适用时）}
- {敏感信息、日志、Prompt 与追踪的最小化和脱敏要求}

**结果输出**

- {持久化数据、任务状态、领域事件或外部副作用}
- {API 响应：`{code, msg, data}`；不得返回敏感信息}

**验收标准**

- {正常路径的可验证业务结果}
- {数据缺失、数据非法、无权访问和依赖不可用时的预期结果}
- {幂等性、状态迁移、审计记录及隐私保护要求（适用时）}

**异常处理与回滚**

- {错误记录、重试或人工处置方式；记录中不得含敏感信息}
- {失败时不得产生的半成品数据或副作用；回滚范围和顺序}
```

## 回滚路线表

|  Stage |  Rollback  Strategy  |  Trigger  |
|- - - - - |- - - - - - - - - - - - - -| - - - - - -| 
|   编码实现 | git checkout - - 丢弃变更  | 编译失败 | 
|   单元测试 | 修复测试或回退代码 | 测试失败率 > 20% | 
|   代码评审 | 修改评审意见  | 🔴问题未解决 | 
|   集成测试 | 回退到上一个稳定版本  |  接口不通  | 
|   预发验证 | 回退到生产版本  | 功能异常 | 
|   上线部署 | 回滚到上一版本镜像 | 冒烟失败 | 
|    线上观测 | 紧急回滚 + 降级  | 错误率 > 1% | 





## 变更管理目录结构

```

├── .harness/changes/
│   ├── {feature-name}/                 
│   │   ├── summary.md              # 变更概述
│   │   ├── db-migrations.sql       # 数据库变更
│   │   ├── rollback.sql            # 回滚脚本
```

每个变更必须包含`summary.md`，记录：

- 变更概述
- 影响模块
- 数据库变更
- API变更
- Redis变更
- 关键约束
- 回滚方案

凡涉及数据库 Schema、约束、函数或触发器的变更，除 `summary.md` 外，必须同时提供：

- `db-migrations.sql`：可重复安全执行的正向迁移脚本。
- `rollback.sql`：仅移除本次新增数据库对象的回滚脚本，并按依赖的反向顺序执行。
