## 1. 交付目标

已登录求职者在没有简历或 JD 的情况下，通过真实任务配置页保存有效求职目标；页面显示目标已保存；Agent 尚未启动时再次保存更新同一个目标。S-06 验证目标保存和“不启动 Agent”的结果，详细启动条件属于 S-07。

```text
求职者登录
→ 进入任务配置页
→ 保存有效求职目标
→ 页面显示已保存，Agent 不启动
→ 修改并再次保存同一个目标
→ 页面回显更新结果
```

## 2. 前置条件与演示数据

- S-01 求职者真实登录和当前 Candidate 身份可用；
- 前端开发服务器、后端服务、PostgreSQL 和 S-06 数据库迁移可用；
- 当前 Candidate 初始没有目标、没有简历、没有 JD；
- 有效数据：Offer 数量 `1`，岗位名称使用脱敏演示文本，筛选条件可为空或填写自由文本；
- 更新数据：修改岗位名称或筛选文本，Offer 数量保持有效；
- 准备非法输入：Offer 数量 `0`、`11`、非整数和空岗位名称；
- 准备 HR 身份，用于验证 S-06 API 的角色边界；
- 准备目标状态为 `achieved` 或 `abandoned` 的数据，用于验证不可修改边界；
- 前端通过真实 API 访问 `/api/v1/job_goals/current`。

## 3. 演示步骤与预期结果

| 步骤 | 操作 | 预期系统结果 | 预期页面结果 |
| --- | --- | --- | --- |
| 1 | 求职者进入任务配置页，输入 Offer `1`、岗位名称和空筛选条件并保存 | PUT 成功；Candidate 获得一个 `active` 当前目标；不绑定简历，不启动 Agent | 页面显示目标已保存；无简历/JD 也不阻止保存 |
| 2 | 修改岗位名称或筛选条件并再次保存 | PUT 成功；返回同一目标 ID；不产生第二个当前目标 | 页面回显最新目标内容；Agent 仍未启动 |
| 3 | 输入 Offer `0`、`11`、非整数或空岗位名称并保存 | 返回 400；原目标不被创建或覆盖 | 保留输入并显示可理解的校验反馈 |
| 4 | 重新进入任务配置页或刷新后恢复登录，再读取当前目标 | GET 成功；返回当前 Candidate 的最新目标 | 页面回显最新目标 |
| 5 | 使用 HR 身份访问 S-06 API | 返回 403；不返回目标数据 | 页面不展示求职目标数据 |
| 6 | 使用 `achieved` 或 `abandoned` 目标修改请求 | 返回 409；原目标不变 | 页面显示目标不可修改 |
