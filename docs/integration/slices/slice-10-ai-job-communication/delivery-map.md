# S10 AI 求职沟通交付目录与场景能力拆解

> 当前阶段：S10-01 已完成 Verify/Close；S10-02 核心能力已完成，但补充真实前端复测发现成功提示语和附件卡片展示问题，当前交付状态为 `integration_blocked`，待整改回归；S10-03 延后
>
> 本文档只记录 S10 的场景地图、能力边界和场景依赖，不定义 API 路径、数据库表、字段名称或具体 Tool 名称。
>
> 跨前后端已确认业务事实以 [`business-baseline.md`](../../../business/business-baseline.md) 中的 `BF-RULE-045` 至 `BF-RULE-057` 为准。

## 1. Slice 主结果

在岗位匹配完成且当前投递已建立沟通会话后，Agent 在授权范围内检索候选人求职证据、回答 HR 问题、交付候选人资料，并主动补齐求职目标判断所需的岗位信息；所有结果均通过系统内会话产生，且可校验、可追踪、可审计。

## 2. 共同前置条件

- 当前用户为已登录且身份已由服务端确认的 HR；
- 当前岗位、Candidate 和 Application 关系已建立，HR 对该投递具有访问权限；
- 当前投递上下文已有可用的沟通会话；
- S-08 已完成岗位匹配和系统内投递；
- Agent 使用的简历、求职目标和求职资料属于当前 Candidate，不能仅凭资源 ID 读取；
- 沟通只产生系统内消息和附件，不产生真实外部招聘平台或真实招聘方副作用。

上述前置条件引用 `BF-FLOW-001`、`BF-OBJECT-006`、`BF-RULE-001`、`BF-RULE-002`、`BF-RULE-008`、`BF-RULE-009`、`BF-RULE-023`；Conversation、Message、Attachment 和 AgentTurn 的技术落地以 S10 Technical Design 为准。

## 3. 场景地图

| 场景 ID | 关键演示场景 | 主要业务结果 | 主要副作用 |
| --- | --- | --- | --- |
| `S10-01` | HR 针对候选人简历经历或项目经历提问 | Agent 基于授权简历证据生成可解释回答 | 在当前会话追加 Agent 消息 |
| `S10-02` | HR 请求候选人提供某项证书或其它求职资料 | Agent 以无额外提示语的附件消息交付资料，HR 看到仿微信文件接收效果并可下载但不能在线预览 | 读取候选人资料、追加仅含附件的消息并保留最小审计记录 |
| `S10-03` | Agent 根据求职目标主动获取 JD 未覆盖的岗位信息 | Agent 发送唯一 query，解析 HR 的二元回答，判断岗位是否继续推进并调整沟通行为 | 在当前 Conversation 追加 Agent 消息；判断结果不改变 Application |

三个场景共享“投递上下文内的授权沟通”，但分别覆盖证据问答、资料交付和主动决策补全；S10-01 已完成交付，S10-02 核心能力已完成但展示整改待回归，S10-03 仍延期。

## 4. 共享能力拆解

| 能力 | 类型 | 责任边界 | 被哪些场景使用 |
| --- | --- | --- | --- |
| 投递会话上下文加载 | 确定性业务能力 | 根据当前身份、Job、Candidate、Application 和会话关系加载授权上下文 | `S10-01`、`S10-02`、`S10-03` |
| 资源归属与访问校验 | 确定性业务能力 | 校验 HR 对当前投递的访问权，以及 Agent 对 Candidate 资料和目标的可用范围 | 三个场景 |
| 消息读取与追加 | 确定性业务能力 | 读取会话消息、追加 Agent 消息，处理发送中/成功/失败和重复请求边界 | 三个场景 |
| 候选人证据检索 | 检索能力 | 从允许使用的简历或结构化候选人证据中返回与问题相关的最小证据集 | `S10-01`、可被 `S10-03` 使用 |
| 候选人资料检索 | 检索能力 | 从当前 Candidate 的附加资料中按资料类型和名称查找候选文件，不暴露内部对象定位 | `S10-02` |
| 结构化结果校验 | 确定性业务能力 | 校验 Agent 输出、检索结果和判断结果，阻止未经校验内容直接成为事实或副作用 | 三个场景 |
| Agent 回复生成 | Agent 能力 | 基于已授权上下文和检索结果生成受约束的回复草稿或结构化行动建议 | `S10-01`、`S10-02` |
| Agent 主动判断 | Agent 能力 | 从未被岗位筛选阶段处理的求职过滤条件中识别 JD 缺口，生成唯一 query，解析二元回答并形成沟通判断 | `S10-03` |
| 幂等与执行追踪 | 确定性业务能力 | 防止重复消息、重复附件发送、重复 query 和重复判断 | 三个场景 |
| 审计与脱敏观测 | 确定性业务能力 | 记录关联 ID、阶段、状态、失败分类、耗时和重试等最小诊断信息 | 三个场景 |

### 4.1 责任边界

```text
API / 会话入口
  → Service：身份、归属、业务规则和事务编排
  → Agent / Workflow：受约束的推理、检索编排和结构化输出
  → Tool：固定能力、输入校验、超时和错误处理
  → Repository：会话、消息、简历、资料和目标的持久化访问
```

Agent 不直接访问 ORM Session、编写 SQL、修改业务状态或发送未经授权的外部请求。若普通 Service 足以完成某项能力，则不强制引入 Agent。

## 5. 场景专属能力拆解

### 5.1 S10-01 基于简历证据回答专业问题

```text
HR 提问
  → 读取当前会话和授权投递上下文
  → 检索与问题相关的简历证据
  → 生成结构化回答草稿
  → 校验证据支持关系和敏感信息边界
  → 追加 Agent 消息
```

| 能力 | 处理方式 | 结果 |
| --- | --- | --- |
| 问题理解 | Agent 将 HR 问题归入经历、项目、技能或其它简历相关问题 | 形成受约束的问题类型和检索意图 |
| 简历证据检索 | Tool/Repository 只读取当前投递绑定简历允许使用的证据 | 返回最小相关证据，不返回内部定位 |
| 证据支持判断 | 确定性校验检查回答是否能由检索证据支持 | 支持则继续；不支持则拒绝编造 |
| 专业回答生成 | Agent 基于证据生成 HR 可读回答 | 形成待发送消息 |
| 无证据处理 | 区分“经历事实范围完整但未出现目标能力”和“资料范围不足/问题超范围/检索失败” | 前者返回“没有相关经历”的受控否定回答；后者返回“信息不足/无法从当前资料确认”等受控结果 |

关键验收结果：回答必须基于固定简历 Fixture 的事实；经历范围完整但目标能力未出现时给出受控否定回答，资料范围不足或问题超范围时不能生成看似确定的专业结论。

### 5.1.1 已确认的 S10-01 业务事实

- 只支持经历、项目、技能等简历相关问题；无关问题使用统一自然语言模板回复。
- Agent 始终使用 S-07 启动时绑定的 Resume；当前 S10 演示不处理多份简历选择。
- CandidateProfile 是绑定 Resume 的结构化投影，不能独立覆盖 Resume。
- Agent 可以读取当前 Application 对应 Conversation 的历史消息，但历史消息只作为上下文，不高于 Resume 的事实来源。
- Resume 与 CandidateProfile 或历史消息冲突时，以 Resume 为准；回答只允许使用 Resume 的直接事实。
- HR 只看到 Agent 生成的回答，不展示完整简历、原文片段或证据摘要；回答可以提及相关项目名称。
- 检索、生成或校验失败但消息通道可用时，发送统一模板回复；消息发送失败且有限重试耗尽时不追加回复，不提供人工兜底或外部手动重新发起。
- 同一请求重试复用已有回答；语义相同但重新提交的问题不属于当前演示验收范围。

### 5.2 S10-02 检索并交付候选人求职资料

```text
HR 请求证书或其它求职资料
  → 读取当前会话和 Candidate 资料授权
  → 检索匹配的 CandidateDocument
  → 生成具备下载能力的系统内消息附件
  → 追加带附件的 Agent 消息并记录最小审计结果
```

| 能力 | 处理方式 | 结果 |
| --- | --- | --- |
| 资料请求识别 | 从 HR 消息中提取资料名称或类型；不读取资料正文 | 形成结构化资料检索意图 |
| 文件名语义匹配 | 通过文件名标准化、关键词和受控别名进行确定性匹配，不使用 LLM | 主演示 Fixture 每次只有一个符合项 |
| CandidateDocument 检索 | Repository 按 Candidate 归属和文件名语义查询 | 返回最多一个成功资料 |
| 附件准备 | 为成功资料创建有效期 7 天的 MessageAttachment | 一条 Agent 文本消息关联一个附件 |
| 附件消息发送 | 消息能力追加带附件的 Agent 消息 | HR 可重复下载，不提供在线预览 |
| 删除与跨 Application | 已发送附件在有效期内独立保留；同一 CandidateDocument 可复用 | 不改变 Application 状态 |
| 幂等与失败 | 同一请求复用 Agent 消息和附件；发送/附件准备失败有限重试 | 重试耗尽不产生可见半成品消息 |
| 最小审计 | 记录检索和附件交付的最小脱敏结果 | 不保存正文、对象定位或内部路径 |

关键验收结果：Agent 能在当前系统内会话中根据文件名语义交付当前 Candidate 的一个求职资料附件，HR 可以重复下载但不能在线预览；该流程不向真实招聘平台或真实招聘方发送文件，且不改变 Application 状态。

### 5.3 S10-03 主动补齐岗位信息并进行求职目标判断

该场景包含“发现缺口并提问”和“获得回答后判断”两个连续验证点。当前受控演示只构造一个未被筛选阶段处理的求职条件和一个 query。

```text
读取 JobGoal 求职过滤条件与岗位结构化信息
  → 排除已在岗位匹配/筛选阶段完成判断的条件
  → 语义识别未处理且 JD 无法确认的条件
  → 生成唯一 query 并作为 Agent 消息写入当前 Conversation
  → 接收 HR 二元回答并进行结构化校验
  → 依据求职目标判断是否继续推进
  → 发送对应的 Agent 沟通消息
```

| 能力 | 处理方式 | 结果 |
| --- | --- | --- |
| 求职目标条件理解 | Agent 从当前 JobGoal 的求职过滤条件中进行语义识别 | 形成未处理的结构化判断条件候选 |
| 已处理条件排除 | 排除已在岗位匹配/筛选阶段完成判断的条件 | 只保留需要主动核验的条件 |
| 岗位信息缺口识别 | 对比未处理条件与受控 JD 信息 | 得到无法由 JD 确认的唯一缺口 |
| Query 生成与发送 | Agent 生成最小二元问题，并写入当前 Conversation | HR 看到主动询问 |
| HR 回答校验 | 对 HR 回答执行二元结果校验 | 得到继续或停止推进所需的结构化结果 |
| 求职目标判断 | 依据求职目标条件和二元回答判断岗位是否继续推进 | 继续推进或停止推进 |
| 沟通行为调整 | 继续推进时回复“好的，了解”；停止推进时回复“感谢沟通，当前不考虑这个岗位了” | 当前 Conversation 形成可见结果 |
| 未回答与解析失败 | 未回答不主动追问；解析失败不作出错误判断，query 保持待处理，技术层可有限重试 | 不追加错误结论 |

“不考虑外包岗位”的示例拆解：

```text
求职目标过滤条件：不考虑外包岗位
岗位 JD：未提供岗位性质
→ 缺口：岗位是否为外包
→ 问题：请确认该岗位是否属于外包岗位
→ HR 回复：是 / 否
→ 判断：停止推进 / 继续推进
→ Agent 回复：感谢沟通，当前不考虑这个岗位了 / 好的，了解
```

## 6. 场景依赖与实施顺序

| 顺序 | 场景/能力 | 原因 |

| 1 | 共享会话授权、消息读写、幂等和失败边界 | 三个场景的共同基础 |

| 4 | `S10-03` 主动信息获取与求职目标判断 | 依赖会话、目标、JD 信息、回答解析和沟通判断 |
