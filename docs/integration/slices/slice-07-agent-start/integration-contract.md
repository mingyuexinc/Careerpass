# Integration Contract：S-07 Agent 投递启动

> Contract ID：`IC-S07-AGENT-START@0.1`。状态：`locked`。
>
> 本契约只覆盖 S-07 的启动校验、当前简历绑定、运行上下文进入 `running` 和当前目标只读查看；结构化 JD 检查、匹配和投递记录由 S-08 负责。

## 1. 基本信息

| 项目 | 内容 |
| --- | --- |
| Slice | `S-07` |
| Scenario | [`IS-S07-01`](integration-scenario.md) |
| Producer | S-07 后端 Agent 启动能力 |
| Consumer | 求职者任务页 |
| 目标查询 | 复用 `IC-S06-JOB-GOAL@0.1` 的 `GET /api/v1/job_goals/current` |
| 运行状态查询 | `GET /api/v1/agent_runs/current` |
| 启动命令 | `POST /api/v1/agent_runs/current/start` |
| 交付边界 | 启动校验、当前简历绑定、运行上下文进入 `running` 和当前目标只读查看 |

## 2. 用户场景与边界

- 当前目标、简历解析状态和画像条件满足时，求职者点击启动 Agent。
- 页面不展示匹配过程；启动完成后进入求职进度页查看 S-08 生成的投递结果、匹配得分和推荐理由。
- 页面继续通过 S-06 当前目标查询展示当前用户自己的目标，并在运行中锁定编辑。
- S-07 启动前检查至少一个成功解析且存在快照的有效岗位；不生成匹配结果或投递记录，具体岗位过滤和结果创建由 S-08 负责。
- 页面不展示匹配资格详情、画像字段、简历原文或 JD 详情。

## 3. 通用响应和身份

所有 S-07 API 响应遵循：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

- 服务端从当前认证身份确定 Candidate，不接受客户端 Candidate、Resume、JobGoal 或 Job 标识作为授权依据。
- 所有目标、简历、画像和运行上下文查询都必须沿 `CurrentIdentity → Candidate → resource` 校验归属。
- 启动请求不携带资源 ID；请求体必须为空对象 `{}`，禁止额外字段。

## 4. 查询当前运行状态

### 请求

```text
GET /api/v1/agent_runs/current
```

无请求体。

### 成功响应

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "state": "not_started",
    "can_start": true,
    "run": null
  }
}
```

`state` 仅允许：

| `state` | 含义 | 页面表现 |
| --- | --- | --- |
| `not_started` | 当前目标没有已创建的运行上下文 | 尚未启动或暂不可启动 |
| `running` | 当前运行上下文已进入运行中 | 展示成功文案，目标只读 |
| `finished` | 当前运行上下文已结束 | 展示结束状态；无投递的 `no_match` 运行在岗位状态改善后允许重新启动新一轮 |

`can_start` 只提供不展开原因的布尔值；`state = not_started` 不代表一定可启动。`run` 为非空时结构固定为：

```json
{
  "id": "<uuid>",
  "status": "running",
  "started_at": "<ISO-8601 datetime>"
}
```

## 5. 启动当前 Agent

### 请求

```text
POST /api/v1/agent_runs/current/start
Content-Type: application/json
```

```json
{}
```

### 成功响应

```json
{
  "code": 200,
  "msg": "agent started",
  "data": {
    "run": {
      "id": "<uuid>",
      "status": "running",
      "started_at": "<ISO-8601 datetime>"
    }
  }
}
```

启动成功表示：服务端已校验目标、解析成功的当前简历和 `matching_ready` 画像，已绑定简历并创建运行上下文。它不表示已经完成 JD 检查、匹配或投递。

### 重复启动

同一当前运行上下文收到重复请求时：

- 返回与首次成功相同的 `200 / 200` 响应结构；
- 返回同一个 `run.id` 和原始 `started_at`；
- 不创建第二个运行上下文；
- 不刷新启动时间；
- 不创建匹配结果或投递记录。

### 错误响应

| 场景 | HTTP / `code` | `msg` | `data` |
| --- | --- | --- | --- |
| 未登录 | `401 / 401` | 通用未授权 | `null` |
| 非求职者身份 | `403 / 403` | 通用无权访问 | `null` |
| 条件不满足或状态竞态 | `409 / 409` | 通用暂不可启动；没有成功解析岗位时为岗位尚未准备完成 | `null` |
| 服务端异常 | `500 / 500` | 通用服务异常 | `null` |

缺少目标、简历未解析成功、画像不可匹配、运行已存在或运行已结束不得通过错误响应暴露具体资格详情。前端正常路径通过 `can_start` 和本地页面状态禁用启动；竞态只展示通用提示并重新查询状态。

## 6. 前端页面消费规则

求职目标模块使用页面级菜单拆分两个前端子页面；该拆分不新增后端目标能力，两个页面仍消费同一个 S-06 当前目标接口。

| 子页面 | 职责 | 允许的业务操作 |
| --- | --- | --- |
| `/candidate/job-goal/create` | 配置当前目标并启动 Agent | `PUT /job_goals/current`、`POST /agent_runs/current/start` |
| `/candidate/job-goal/view` | 以只读横向列表展示当前目标的岗位、Offer 数量和创建时间 | `GET /job_goals/current` |

查看页将当前目标安全投影包装为单元素列表；这只是 RecyclerView 类似的前端组件形态，不代表新增目标历史、版本或多目标能力。

| 场景 | 前端行为 |
| --- | --- |
| 创建页进入 | 读取当前目标和当前运行状态，显示配置和启动区域 |
| 查看页进入 | 读取当前目标，以列表行显示；不显示配置和启动控件 |
| 目标为空 | 查看页展示空状态和创建入口；创建页保留目标表单且启动按钮禁用 |
| `can_start = false` 且未运行 | 展示“尚未满足启动条件”，不展示原因详情 |
| `can_start = true` | 启动按钮可用 |
| 启动提交中 | 禁止重复点击，不创建本地运行结果 |
| 启动成功 | 创建页展示约定成功文案，目标进入只读；查看页显示已锁定列表行 |
| 重复成功 | 与首次成功使用同一页面结果 |
| `409` 竞态 | 展示通用提示并重新读取运行状态，不建立“启动失败”业务状态 |

## 7. S-08 交接

S-07 成功后形成 `AGENT-RUNNING-HANDOFF@0.1`：

- 交接触发点是运行上下文事务提交并进入 `running`；
- S-08 通过 `run_id` 在服务端按 Candidate 归属读取目标快照、绑定简历和画像引用；
- 前端不接收完整交接对象；
- S-08 消费交接后才检查可用结构化 JD；
- 重复消费交接不得创建新的运行、匹配或投递记录。

## 8. 安全边界

不得出现在普通 API 响应、日志或追踪中的内容：

- 简历原文和联系方式；
- 画像原值和匹配资格明细；
- 结构化 JD 原文或内部文件定位；
- 令牌、密码、模型原始响应和完整异常堆栈。

允许的最小诊断字段：关联 ID、处理阶段、状态、失败分类、耗时和重试次数。
