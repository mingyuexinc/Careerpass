## 1. 已锁定的跨端行为

开发者演示目标是 HR 上传多份 JD 后，页面逐文件展示上传处理结果。当前业务事实确认：S-02 创建 Job、保存文件并建立 S-03 解析任务交接，不代表 JD 已经完成结构化解析。

因此以下字段不能由 S-02 上传响应直接提供或由 Mock 擅自伪造：岗位名称、公司、地点、薪资、摘要和岗位版本。它们是否以及何时由 S-03 解析结果提供，属于后续 Contract 版本或场景。

本 Contract 锁定以下最小交付语义：

- `created` 和 `duplicate` 在本次页面交互中均映射为“上传成功”；
- `failed` 映射为“上传失败”；
- 页面逐文件展示上传文件名及“上传成功/上传失败”状态标识；
- 页面不显示“解析中”、解析结果或岗位摘要；
- `job_id` 和 `task_status` 仅作为接口内部及后续 S-03 交接数据保留，不作为页面解析状态展示；
- S-02 页面只负责选择多份 `.md` 文件，选择完成后立即提交并逐文件展示上传结果，不设置额外确认按钮；
- 非 `.md` 文件属于不合规输入并映射为“上传失败”；
- 岗位列表、岗位详情、岗位删除、岗位名称、公司、地点、薪资、摘要、版本和解析结果不属于本 Contract，分别由后续 Slice 或 Contract 版本定义。

## 2. 候选接口边界

### `POST /api/v1/jobs`

| 项目 | 约定 |
| --- | --- |
| 请求 | 已认证 HR 通过 multipart 字段 `files` 提交一份或多份 JD |
| 文件格式 | 仅接受 Markdown（`.md`），正文编码必须可读 |
| 响应 | `{code, msg, data}`，`data.results` 逐文件返回结果 |
| 结果 | `created`、`duplicate`、`failed` |
| 创建成功 | 返回 `job_id` 和排队状态，不表示 JD 已解析成功 |
| 重复成功 | 返回已有 `job_id`，不重复创建 Job 或解析任务 |
| 失败 | 返回安全失败分类，不返回原始异常、文件正文或内部路径 |

当前后端技术设计和 Schema 是本接口的实现证据；Contract 锁定不等于真实联调已经完成，真实联调仍须按 `IS-S02-01` 留存证据。

## 3. 必须覆盖的 Contract 分支

| 分支 | 页面结果 |
| --- | --- |
| 合法文件创建 | 显示“上传成功”，不显示解析状态或解析结果 |
| 相同内容重复上传 | 按幂等成功处理，页面显示“上传成功”，不新增第二条业务资源 |
| 单文件失败 | 显示该文件“上传失败”，其他文件结果保留 |
| 非 HR 或无效身份 | 拒绝操作，不泄露资源信息 |

## 4. 锁定条件

- 前端不再把上传结果扩展成完整岗位对象；
- 后端响应、S-02 专用前端类型和页面状态映射已完成对照；
- 查询、删除、岗位摘要、版本和解析结果已明确不属于本 Contract；
- `IS-S02-01` 的演示步骤和预期结果已同步；
- 真实联调通过后，才能将 Scenario 标记为 `integration_delivered`。
