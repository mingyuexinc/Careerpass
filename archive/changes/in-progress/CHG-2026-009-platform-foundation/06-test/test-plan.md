# 测试计划

## 单元测试

- Settings：开发、测试、生产三种配置；缺失必填项、非法 URL、生产环境错误调试开关均失败且不显示密钥。
- 响应/异常：成功响应、Pydantic 验证错误、已知业务异常、未知异常均满足统一协议。
- Request ID：合法上游 ID 被透传；缺失时生成；非法或过长 ID 被替换；日志上下文与响应一致。
- 日志脱敏：Authorization、Cookie、password、token、数据库 URL、嵌套敏感字段均不出现在日志事件中。
- 生命周期：客户端创建/关闭顺序正确；关闭操作幂等。
- 数据库和任务边界：API/Service/Agent/Workflow 层不 import Session 或执行 SQL；任务输入校验和错误脱敏可测试。

## 集成测试

- 使用独立 PostgreSQL 与 Redis 实例运行 Alembic 空基线，重复 `upgrade head` 不失败。
- 应用在依赖健康时 `/health/live`、`/health/ready` 返回 200 和统一结构。
- PostgreSQL 或 Redis 故障时，live 仍为 200，ready 在超时内返回 503 且不泄露网络地址或堆栈。
- Celery eager/mock worker 模式验证探针任务的成功、可重试失败和状态映射；不产生业务数据。

## 权限、幂等性与状态迁移

本阶段不存在业务资源、候选人身份或业务状态机；因此不以虚假的默认用户替代权限实现。测试应确认健康端点完全不查询资源。

探针任务以相同幂等键重复提交时不得产生额外业务副作用；目前仅验证幂等接口约定。正式任务状态表、权限校验和状态机将在首个业务闭环的变更中测试。

## 验收场景

1. 开发者复制 `.env.example`、补齐本地值后，可启动应用、运行 Alembic 和测试。
2. 运维移除数据库密码后，启动/ready 以安全方式失败，日志与接口中均没有密码或连接串。
3. 调用方传入 `X-Request-ID` 后，该 ID 在响应头与日志相关字段一致。
4. 依赖暂时不可用时，服务不阻塞、不崩溃，且只由 readiness 报告不可用。
5. 在任意 API 路径和异常路径中，响应外层字段始终为 `code`、`msg`、`data`。
