# L0 API 响应契约

## 决策

CareerPass 的所有 HTTP API 响应（包含成功、参数校验失败、认证/授权失败、资源不存在、冲突、依赖不可用和未处理异常）均使用以下外层 JSON 结构：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

字段名为 `code`、`msg`、`data`，大小写固定；不得使用 `message`、`result`、`error` 或其他响应信封字段替代 `msg`。HTTP 状态码仍由 HTTP 协议表达，`code` 用于统一业务结果表达；二者在当前基础契约内保持语义一致。

## 字段语义

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `code` | Integer | 必填。成功为 200；失败仅使用接口协议定义的 400、401、403、404、409、500。依赖未就绪可使用 HTTP 503，但信封 `code` 为 500，避免扩展未评审的业务码。 |
| `msg` | String | 必填、面向调用方的安全简述；不得包含堆栈、数据库信息、令牌、文件内容或个人信息。 |
| `data` | Object / Array / Scalar / null | 必填。成功时承载业务数据；错误时为 `null`。 |

## 分页契约

分页接口的 `data` 必须为对象，包含 `list`、`total`、`page`、`size`。不得在顶层增加分页字段。

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "list": [],
    "total": 0,
    "page": 1,
    "size": 20
  }
}
```

## 请求追踪契约

`X-Request-ID` 是可选请求头。服务端必须接受合法的调用方值，或在缺失/非法时生成新的值；该 ID 必须写入响应头和结构化日志上下文。它不属于 JSON 响应体，不得含个人信息或密钥。

## 适用与变更控制

- 本契约适用于 `/api/v1/*` 以及 Phase 0 引入的健康检查端点。
- 单一端点不得声明例外响应信封。文件下载、流式传输等非 JSON 协议如有需要，必须由后续独立 contract 变更批准。
- 修改字段名、错误码语义或分页外形，必须先更新接口协议、编码规范并新建变更包；不得在实现中临时兼容 `message`。
