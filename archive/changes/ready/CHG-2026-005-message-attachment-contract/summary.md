# 消息附件资源契约

## 变更概述

新增独立的 `Attachment` 文件资源，用于承载消息附件；其文件与解析元数据与求职者资料保持一致的结构。

## 影响模块

- AI 求职沟通
- 文档处理
- Repository 数据访问

## 数据库变更

新增消息附件表，使用 `message_id` 外键关联消息；候选人归属通过“消息 → 会话 → 投递 → 求职目标”链路推导，不保存冗余 `candidate_id`。

## API变更

消息的 `attachment_ids` 对应附件资源 ID；附件上传/查询 API 将在实现阶段单独定义。

## Redis变更

无。

## 关键约束

- 每个附件只属于一条消息；删除消息时级联删除附件记录。
- 附件解析使用既有 `parse_status_enum`，并记录结构化解析数据或失败原因。
- Repository 必须通过消息归属链校验当前候选人。

## 回滚方案

实际数据库迁移回滚时先删除消息附件表及其外键、索引；本次仅修订文档契约。

## 关联与实施状态

- 关联需求/变更包：CHG-2026-007（资源归属锚点）。
- 当前状态：已确认，待实现。

## 验收标准

- 附件与消息是一对多关系，且只能经消息归属链由所属候选人访问。
- 删除消息时附件记录级联删除，解析状态与失败原因可追踪。
