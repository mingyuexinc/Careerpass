# 候选人附加资料与消息附件 MVP 契约

## 变更概述

将候选人附加资料和消息附件从 Deferred 提升为受控 MVP 能力。候选人附加资料是可复用的原始文件资源，不参与解析、画像、匹配或 Agent/LLM 上下文；消息附件仅记录某条会话消息对候选人本次明确选择且归属一致的资料引用，不重复保存文件或资料正文。

## 影响模块

- 候选人资料准备与本地对象存储
- AI 求职沟通
- 接口协议、数据模型与业务规则

## 数据库变更

新增仅供存储适配器和 Repository 使用的 `stored_file_objects` 内部对象目录、MVP 适用的 `candidate_documents` 和引用型 `message_attachments` 数据模型；内部对象目录以内容摘要唯一约束实现去重，并仅在无资源引用时可被清理。本变更包提供评审用 SQL 与回滚脚本，实际运行仍须在候选人资料准备实现变更中新增 Alembic revision。

## API 变更

- `POST /api/v1/candidate_documents/upload`、`GET /api/v1/candidate_documents` 从 Deferred 提升为 MVP。
- 发送消息请求增加可选 `candidate_document_ids`；消息响应和列表返回最小附件引用信息。

## Redis 变更

无。候选人附加资料不创建异步解析任务，不使用 Celery。

## 关键约束

- 附加资料只能作为候选人明确授权的系统内消息原始附件，不替代正式简历、候选人画像或下游业务前置条件。
- 附加资料不保存 `parse_data`、`parse_status` 或 `failure_code`，也不关联 `AsyncTaskRun`；它只能通过外键引用内部文件对象。
- 内部文件对象按内容摘要去重；清理前必须事务内确认无 `resumes` 或 `candidate_documents` 引用，临时、写入中及无引用对象的清理宽限期为 1 小时。
- 附件引用前必须校验当前候选人、会话所属候选人、资料归属与资料对象存在。
- Agent 不得自行上传、选择或对外发送候选人资料；系统仅模拟内部发送。

- 当前状态：proposed；已完成文档契约，待候选人资料准备与 AI 沟通实现时落地。

## 验收标准

- 候选人可上传并查询本人附加资料，非所有者无法访问。
- 候选人可将本人已上传且明确选择的资料附加到其会话消息，非所有者无法访问或引用。
- `message_attachments` 不重复存储文件或资料正文。
- 附加资料不会使候选人绕过正式简历、画像和活跃目标的就绪条件。

## 回滚方案

将资料和消息附件标记恢复为 Deferred，并删除本次新增引用契约；不涉及当前运行时迁移或外部发送回滚。
