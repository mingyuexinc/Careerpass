# 候选人画像唯一结构化事实来源

## 变更概述

明确 MVP 中 `candidate_profiles` 是下游模块读取简历结构化事实的唯一来源，`resumes` 只保存原始文件、归属与解析生命周期，不新增或使用 `resumes.parse_data`。

## 关键约束

- 画像字段必须覆盖岗位匹配、投递和 AI 沟通在 MVP 中实际需要的简历信息。
- `target_job_titles` 统一为至少一个非空字符串的数组；单个目标职位也使用单元素数组，避免字符串与列表两种持久化形态并存。
- 简历解析成功时，校验后的结构化结果与画像在同一工作流中原子持久化。
- 下游新增简历字段时，先扩展 `candidate_profiles` Schema，再以原始简历文件发起新版本解析并验证结果；不得以中间 JSON 或历史未校验输出作为业务读取来源。

## 影响范围

- 本次仅更新 MVP 范围、业务模型和数据模型文档。
- 不新增数据库字段、API、Celery 配置或运行时迁移。

## 验收标准

- 文档能够明确区分：`resumes` 管理文件和解析状态，`candidate_profiles` 管理已校验的业务结构化事实。
- 任一新增下游简历字段均可依据文档确定其 Schema 演进与重解析路径。
- MVP 不出现两个并列的简历结构化事实来源。

## 回滚方案

撤销本变更包所述文档边界，恢复为未明确唯一结构化事实来源的表述；不涉及运行时数据或数据库迁移回滚。
