# 影响分析

## 受影响模块与边界

| 模块 | 影响 | 所有权/权限影响 | 备注 |
| --- | --- | --- | --- |
| 候选人资料准备 | 画像改为简历解析工作流的确定性原子派生结果；目标职位为解析必填事实 | 简历和画像归属仍由简历的 `candidate_id` 链路确定 | 不新增用户可见任务接口或独立画像任务 |
| 文档解析 | 明确任务重试不等于资源失败 | Worker 必须在处理前校验资源授权 | 不允许半成品结构化结果 |
| 岗位 JD 管理 | 后续 JD 解析复用任务模型 | 不在本变更中扩展岗位所有权模型 | 不新增 JD 接口 |
| 岗位匹配 | 后续匹配任务可复用运行模型 | 匹配归属仍由目标锚定 | RAG 未被提升为固定依赖 |

## 契约与数据影响

- API：无。
- 数据库与 Alembic：新增 `async_task_runs` 数据模型、相关枚举、全量幂等唯一约束与待投递部分索引；本变更包提供评审用 SQL，实际运行仍须新增工程内 Alembic revision。
- Redis/Celery：实现时必须由独立、单实例 Dispatcher 消费 `queued + celery_task_id IS NULL` 的可靠入队记录，Broker 接受后回填任务 ID；Dispatcher 不由 Celery Beat 驱动。Celery 任务配置仍负责有限重试、退避和超时，并以 `celery_task_id` 与业务任务记录关联。
- LLM、Prompt、追踪脱敏：模型输出和失败信息不得以原文形式写入任务记录。

## 风险与缓解

| 风险 | 等级 | 缓解措施 |
| --- | --- | --- |
| 任务状态与资源状态混淆导致过早标记失败 | high | 明确两类状态语义与重试期间资源保持 `processing` 的规则 |
| 通用任务表泄漏候选人资源存在性 | high | 归属由资源链推导，所有查询和重试经 Repository 校验 |
| 将 Embedding 误实现为解析固定步骤 | medium | 将其改为按匹配需求显式触发的条件能力 |
| 在业务表重复保存 Celery 运行时策略 | medium | 仅持久化业务关联与审计字段，重试和超时由 Celery 配置管理 |
| 将画像误实现为独立推荐或异步任务 | medium | 画像与成功解析结果原子写入；目标职位仅接受已校验的简历提取事实 |
