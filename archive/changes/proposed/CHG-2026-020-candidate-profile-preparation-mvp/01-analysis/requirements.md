# 候选人资料准备需求分析

> 标记说明：
>
> - 【开发者填写】：必须由开发者作出明确裁决。
> - 【共同补全】：可由大模型起草，开发者负责复核确认。
>
> 本文依据当前 MVP 范围裁决和已实现的候选人资料准备行为回填。它用于受控 Demo 演示，不将公开运营、规模化或生产运维能力作为本期目标。开发者已确认本需求分析，阶段 1 已完成；后续阶段仍须按阶段台账串行门禁执行。

## 1. 背景与业务价值【开发者填写】

- 要解决的用户问题：已认证候选人需要在受控 Demo 中上传和管理本人已脱敏的正式简历及候选人附加资料，并能查询本人资料的受控元数据与上传结果；无需接触文件内部定位或原文。
- Demo 成功标准：使用已认证的测试候选人和脱敏 PDF，候选人上传正式简历后获得 `201` 和上传已受理结果；相同幂等键重放获得同一简历；候选人仅能列出本人资料；附加资料能上传和按类型查询，响应不含 `storage_key`、原文或物理路径。
- 不实现本模块对核心闭环的影响：候选人不能提供简历这一核心输入，后续文档解析、画像、匹配和系统内投递记录的演示路径无法开始。
- 本模块优先级与原因：MVP 基线能力。它为核心求职闭环提供候选人自主、受控且可追踪的资料入口；不承担画像或后续准入决策。

## 2. 用户、角色与授权【开发者填写】

- 使用者/触发者：已认证候选人本人，通过受保护的 HTTP API 上传、列出和查询自身资料状态。
- 资源所有者：`Resume` 与 `CandidateDocument` 均归创建它们的 `Candidate` 所有；底层 `StoredFileObject` 是受控技术资源，不是可供客户端直接读取的业务资源。
- 各角色权限：当前候选人可创建、列出和查看本人正式简历及其资料元数据，也可创建、列出和按类型筛选本人附加资料；未认证用户、其他候选人、HR 和 Agent 均无正文读取、下载、上传或自主选择权限。
- 资源归属/访问授权链：Bearer Access Token → `CurrentIdentity(user_id, candidate_id)` → Repository 按 `candidate_id` 过滤或校验资源归属 → Service/API 返回最小化 DTO。
- 越权与未认证访问：缺失、无效或过期认证被拒绝；跨候选人资料查询返回安全的不可访问结果（列表为空或资源查询 `404`），不暴露资源是否存在、原文、对象键或路径。

## 3. MVP 范围裁决【开发者填写】

- 本期必须交付：正式简历及候选人附加资料的受控上传与列表；本地对象存储抽象下的服务端生成不透明对象键；上传幂等；候选人级归属校验；资料元数据和上传结果的受控查询。
- 本期明确不做：候选人画像的生成、持久化、查询或编辑；简历/附加资料正文下载；自动脱敏、人工脱敏确认或修复；资料完整度评分、求职状态派生、目标职位推荐；跨简历画像版本管理；匹配、投递或 AI 沟通准入判断。
- 延期能力：云对象存储和通用文件中心、批量资料操作、公开多租户运营、HR 直接读取、Agent 自主上传/选择/读取正文、生命周期运营和高可用存储治理。
- 与核心用户路径的关系：模块完成“认证候选人 → 上传已脱敏正式简历 → 形成本人可查询的资料记录”的上游步骤。解析、画像和其后的匹配/投递均为其他模块职责。
- 上游前置模块与下游消费者：上游为认证与当前身份解析；本模块不调用文档解析 Service、Dispatcher、Worker 或任何解析能力。正式简历完成上传、归属校验和对象 `ready` 后，G2 在同一 PostgreSQL 事务中创建或复用 `ResumeParseRequestV1` 对应的 queued `AsyncTaskRun`；该交接不是解析执行调用。文档解析模块只消费 G2 已创建或复用的 queued 任务并负责后续处理。
- 跨开发包依赖与契约登记：生产者为本模块，消费者为 CHG-021；契约为 `.harness/contracts/resume-parse-request-v1.yaml` 的 `ResumeParseRequestV1@v1`；联合评审标识为 `JCG-2026-020-021-RESUME-PARSE-V1`。
- 最小实现：认证候选人上传一个脱敏 PDF 正式简历，获得候选人自有的简历 ID 和受控资料元数据；附加资料可安全上传和列出。
- 不纳入理由：这些能力不增加本模块“资料受控交接”的演示证据，且会引入文档解析、匹配、投递、沟通、生产运营或隐私治理的内部耦合。

## 4. 最小行为与输入输出【开发者填写】

| 项目 | 说明 |
| --- | --- |
| 触发者与入口 | 已认证候选人调用 `POST /api/v1/resumes`、`GET /api/v1/resumes`、`POST /api/v1/candidate_documents` 和 `GET /api/v1/candidate_documents`；API 统一返回 `{code, msg, data}`。 |
| 处理对象与来源 | 候选人主动提交的已脱敏正式 PDF 简历，或允许类型的候选人附加资料；候选人身份来自 Access Token，不接受客户端指定 `candidate_id`。 |
| 输入约束 | 正式简历为允许的 PDF 类型并受大小限制；附加资料的类型和展示名称受 Schema 校验；可选 `Idempotency-Key` 必须为合法 UUID；重复键配合相同请求重放原结果，配合不同内容/名称返回安全 `409`。 |
| 最小处理 | 校验身份和输入；将字节通过受控对象存储写入服务端生成的不透明键；在对象 `ready` 且候选人归属成立后，Repository 在同一事务中创建或复用对象、正式简历、上传幂等关系和 `AsyncTaskRun(status=queued)`；失败时清理未引用临时对象。 |
| 输出与消费者 | 正式简历上传返回 `201 / UPLOAD_ACCEPTED`、`resume_id` 和 `parse_status=processing`；附加资料只返回自身 ID 和最小元数据。G3 消费 G2 已创建的 queued 任务，本模块不调用下游解析执行逻辑。 |
| 保留方式 | 文件仅保存在受控对象存储根目录下，数据库保存不透明键、摘要、类型、大小、引用和状态；客户端响应、普通日志与追踪不保存原文或可直接访问定位。 |
| 明确不做 | 不提供文件正文/路径下载 API；不解析任何资料；不提供文件版本、批量操作、Agent 自主处理或下游业务准入。 |

## 6. 安全、隐私与模块边界【开发者填写】

- 敏感数据边界：仅接受候选人上传前已脱敏的资料。原文、联系方式、内部对象键、绝对路径、凭证、模型原始输出和异常堆栈不得进入 API 响应、普通日志、追踪或 Prompt。
- 最小化要求：API 返回资源 ID、展示名、类型和受控状态；不返回原文、摘要、对象键、物理路径、存储 URL 或解析中间结果。日志与追踪仅允许关联 ID、阶段、状态、失败分类、耗时和重试次数等脱敏诊断。
- 不得跨越的边界：本模块不读取存储正文之外的下游业务结果，不访问画像、匹配、投递或沟通资源，也不决定下游业务准入。跨模块交接只允许输出固定版本的资源 ID、候选人归属和契约版本，不传递正文、路径、对象键、模型参数或自由指令。数据访问只经本模块 Repository；Service 不直接使用 ORM Session 或 SQL。
- 审计、授权与合规：上传请求通过认证和候选人归属校验；幂等冲突、非法文件和存储失败使用安全错误响应。本模块不形成对外副作用或授权下游业务动作。

## 7. 验收与演示【共同补全】

- 使用两个已认证候选人和脱敏样本：候选人 A 上传正式 PDF，收到 `201`、自身简历 ID 和 `processing`；A 用相同幂等键重放后得到同一 ID；用同一键提交不同内容得到 `409`。
- A 上传附加资料并按类型查询，响应仅含最小元数据；候选人 B 的列表不含 A 的资料，且无法通过资源 ID 取得 A 的受限资源。
- 检查正式简历创建后存在一致的对象元数据、资料记录和幂等关系。
- 对外可观察结果仅为统一 API 响应和候选人自有资料状态；不得以日志或直接查看对象存储目录作为演示证据。

## 8. 影响分析与发布策略【共同补全】

- 受影响模块：认证提供当前身份；共享对象存储提供受控写入；数据库保存资料元数据和幂等关系。下游解析模块不属于本模块的实现或验收依赖。
- 数据与接口：使用 `stored_file_objects`、`resumes`、`candidate_documents` 及其幂等/归属关系；对外涉及资料上传和列表 API，保持统一响应格式。数据库演进与回滚以本开发包 `04-data/` 中现有 Alembic 记录为准。
- 兼容、发布与就绪：Demo 发布前核对认证、数据库迁移和对象存储根目录；失败时不产生可见半成品资料记录。当前不是生产发布计划，不声明多租户、高可用、灾备或运营 SLA。
- 演示证据与非生产声明：仅使用已脱敏测试文件，在受控环境重复上传、幂等、隔离和本人资料查询；不覆盖公开用户、真实 HR、真实投递、规模容量或长期运行可靠性。
- 风险、假设与缓解：对象存储不可用会阻止资料受理，采用失败清理与安全响应避免半成品；候选人误上传敏感信息由上传前脱敏约束和最小化暴露共同缓解，不在 MVP 内自动识别或修复。
