# 阶段 2：外部技术能力预验证记录

## 裁决

经开发者确认，本模块阶段 2 唯一需要登记的外部技术能力仍为 PostgreSQL/Repository。认证、统一响应和本地对象存储属于已存在的共享能力复用；本模块不启用或验证 Dispatcher、Celery Worker、MinerU、Qwen、Redis 或其他解析执行技术能力。

`ResumeParseRequestV1` 是跨模块内部契约，不是新的外部技术能力。阶段 2 只验证现有 PostgreSQL/Repository 等外部技术能力是否可复用；不把尚未实现的契约交接业务行为、G3 任务消费、解析执行或画像写入作为本阶段通过条件。契约交接的字段、归属、对象状态、幂等和事务边界在阶段 3 设计、阶段 4 拆分及阶段 5/6 实现验证中处理。

跨模块交接的职责边界固定如下：候选人资料准备模块只交接固定版本的资源 ID、候选人归属和 `task_version=v1`，不调用 G3 Service、Dispatcher 或 Worker，也不传递正文、路径、对象键、模型参数或自由指令；G2 在同一 PostgreSQL 事务中创建或复用 queued `AsyncTaskRun`，文档解析模块只消费该既有任务并负责后续执行，不创建第二个任务。

## PostgreSQL/Repository 验证结果

状态：`passed`

验证目的：确认资料上传闭环依赖的 PostgreSQL/Repository、认证归属链和本地对象存储抽象可用，并确认本次契约交接不引入新的外部技术能力。契约交接的具体业务实现不属于阶段 2 的验证范围。

既有验证证据：

- `06-verification/test-report.md` 的子任务 1：隔离 PostgreSQL 完成迁移升级/回滚/再次升级，验证资料表、约束、枚举和更新时间触发器。
- `06-verification/test-report.md` 的子任务 3：隔离 PostgreSQL、Redis 与本地对象存储集成测试通过，验证上传、幂等、对象复用、候选人隔离、统一响应和安全字段边界。
- `06-verification/test-report.md` 的子任务 0-3：Repository 访问均通过候选人归属校验，Service/API 未直接访问 ORM Session 或 SQL。

验证结论：上述证据证明 PostgreSQL/Repository、认证归属链和本地对象存储抽象可作为本模块已验证前置能力复用。本次没有新增需要供应商级首次验证的外部技术能力；`ResumeParseRequestV1` 为内部跨模块契约，其业务交接实现留待后续阶段。阶段 2 外部技术能力预验证通过。

## 后续阶段契约交接验证计划

以下 H1–H8 属于阶段 5/6 的实现与运行验证计划，不是阶段 2 的通过条件。执行时使用隔离 PostgreSQL、脱敏测试数据和注入式对象存储替身；验证记录只保留关联 ID、处理阶段、状态、失败分类和耗时。

| 编号 | 验证场景 | 预期结果 |
| --- | --- | --- |
| H1 | 候选人、简历和对象归属一致，且对象为 `ready` 的合法交接 | `ResumeParseRequestV1` 通过校验并成功提交交接；不调用 G3 Service、Dispatcher 或 Worker |
| H2 | 请求加入路径、URL、对象键、正文、模型参数或未知字段 | `extra="forbid"` 或等价边界拒绝请求，不创建交接结果 |
| H3 | 候选人 A 的请求引用候选人 B 的简历 | Repository 归属校验失败，不创建越权交接或任务 |
| H4 | 对象不存在或对象状态不是 `ready` | 交接失败，不创建有效解析任务，不暴露对象定位信息 |
| H5 | 同一候选人、简历和 `task_version=v1` 重复交接 | 只保留一个有效交接/任务结果，不产生重复任务 |
| H6 | 交接事务失败或发生回滚 | 不产生悬挂交接、重复任务或覆盖既有资源 |
| H7 | Service/API 层级检查 | Service 不直接访问 ORM Session/SQL，交接读写全部经 Repository |
| H8 | 日志和验证产物脱敏检查 | 不包含简历正文、对象键、路径、凭证、模型响应或敏感异常堆栈 |

H1–H8 不等同于 G3 的 Dispatcher、Worker、MinerU、Qwen 或画像全链路验收；它们应在阶段 5/6 按受影响开发包的门禁分别执行。
