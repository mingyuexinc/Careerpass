# 上传接口幂等契约

## 变更概述

为正式简历与候选人附加资料上传引入客户端 `Idempotency-Key` 的持久化约束。相同候选人的同一上传端点使用相同 Key 重试时复用首次创建结果；同 Key 但文件内容或展示名不同返回安全的 `409` 冲突。

## 影响模块

- 候选人资料准备：简历和附加资料上传接口。
- 数据模型：`resumes`、`candidate_documents` 的上传幂等键与局部唯一约束。
- 接口协议：统一上传幂等、附加资料 REST 路径与解析失败提示映射。

## 数据库变更

新增两个可空 UUID 字段及仅对非空值生效的候选人级唯一索引。Key 随资源记录保留；MVP 不提供已引用资源或任务审计清理，因此不设置独立过期时间。

## API 变更

- 正式简历：`POST /api/v1/resumes`
- 附加资料：`POST /api/v1/candidate_documents`
- 两个上传入口均支持 `Idempotency-Key`。

## Redis 变更

无。

## 关键约束

- 幂等键校验必须经过 Repository，并与资源创建原子执行。
- 幂等键、文件摘要和内部对象定位均不得返回客户端或写入普通日志。
- 解析终态失败仍以 `failure_code` 表达，不与 HTTP 错误混用。

## 回滚方案

按 `rollback.sql` 先移除唯一索引，再移除新增字段；不会删除既有简历、附加资料或对象文件。
