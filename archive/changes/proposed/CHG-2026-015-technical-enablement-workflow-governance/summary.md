# 技术使能与工作流治理

## 变更概述

新增技术使能能力与工作流治理文档，并更新 MVP 范围、业务规则、工程结构和开发任务模板。该契约以“最小公共底座 + 业务闭环纵向切片 + 按触发条件演进”为原则，明确 Agent 工作流调度、RAG 分层和技术能力首次交付的边界。

## 影响模块

- 候选人资料准备与文档解析
- 岗位 JD 管理与岗位匹配
- 投递、进度与 AI 求职沟通
- Agent 编排、工作流、检索能力与开发变更流程

## 数据库变更

无。本变更仅定义未来工作流运行记录、审计事件等对象的治理边界，不新增 Schema 或 Alembic revision。

## API 变更

无。本变更不新增运行时路由、请求或响应字段。

## Redis 变更

无。本变更不新增队列、缓存键或 Worker 配置。

## 关键约束

- Agent 仅产生经 Pydantic 校验的结构化计划，且只能调度代码注册的工作流。
- 计划、工作流及检索能力不得绕过 Repository、归属校验、状态机、授权和敏感信息保护。
- RAG 能力按 R0-R4 分层演进；向量召回、重排序和混合检索不是无关模块的统一前置条件。
- 可视化编排、动态流程发布和工作流运营台明确延期。

## 关联与实施状态

- 关联需求/变更包：CHG-2026-009、CHG-2026-013
- 当前状态：proposed；已完成文档契约草案，待评审后进入 ready。

## 验收标准

- 后续模块可依据文档判定所需技术能力的类别、状态、首次交付、启用条件和延期边界。
- Agent 受控工作流调度与可视化工作流平台的范围被明确区分。
- 开发设计和任务拆分模板能标注业务闭环、技术能力、首次交付/复用和集成验证。
- 不引入任何代码、数据库、API 或 Redis 运行时变更。
